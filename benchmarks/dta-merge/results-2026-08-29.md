# dta_merge source-combination benchmark results

Run date: 2026-08-29.

Environment: Apple M4 Max, 128 GB RAM, macOS 26.5.0, R 4.6.1,
dtatools 0.6.0 (development) built from commit `b965bd3` on the
`docs-arrow-ipc-interchange-format` branch and installed into a private
benchmark library; dplyr 1.2.1.

## Design

`dta_merge()` accepts a data frame or a `.dta`/`.arrow` file path for either
side, so this run measures every input-source combination on one merge. The
master table is the canonical synthetic fixture
(`target/large-scale/datasets.tsv`, creator `stata-first-save`): 231,956 rows
at 100 MB and 2,320,123 rows at 1 GB, 40 columns, unique `id` key. The using
table is derived from it: the first half of the master ids plus 4% unmatched
new ids, with two payload columns, saved as both `.dta` and `.arrow` (the
master's Arrow copy comes from `save_arrow()` on its `read_dta()` model).

`benchmarks/dta-merge/worker.R` runs one combination per process: inputs
marked `mem` are loaded before the timer (by `read_dta()` or `read_arrow()`
according to extension) and path inputs stay strings, so their file read is
timed inside `dta_merge()`. Each process runs one untimed warm merge, then
timed iterations (7 at 100 MB, 5 at 1 GB) of
`dta_merge(x, y, by = "id", relationship = "1:1")` with a full garbage
collection between them. The context rows time `base::merge(all = TRUE,
sort = FALSE)` and `dplyr::full_join()` on the same tables converted to plain
doubles and characters and preloaded — those engines cannot take file paths
and do not implement Stata missing-value identity, master-wins conflict
resolution, relationship validation, or the `_merge` indicator, so they bound
the in-memory rows rather than compete like-for-like.

All values are medians in seconds. Every dtatools combination returned the
same 241,234 / 2,412,927 result rows.

## Reading the numbers

The file-path rows behave as they should: a from-file merge costs the file
read plus the merge, with no anomalous overhead. On the y side the using
table is small, so passing a path adds only ~0.01 s over memory at either
scale, and the `.dta`/`.arrow` difference is within noise.

On the x side the step from memory to path is larger than the raw read
because the warm in-memory rows are flattered by ALTREP caching. `read_dta()`
and `read_arrow()` return columns deferred through ALTREP; assembling the
merged output touches every column and materializes it once. When x lives in
memory across iterations, that materialization happened during the untimed
warm merge, so the timed iterations reuse cached columns. When x is a path,
every iteration re-reads the file and pays first-touch materialization again.
At 1 GB the x-from-`.dta` step over memory is 0.387 s, of which 0.184 s is
the warm `read_dta()` itself (`benchmarks/arrow-interchange`
`results-2026-08-29.md`) and the rest is that one-time column
materialization; the `.arrow` step decomposes the same way over its 0.097 s
read. A single cold merge-from-file therefore costs about the same whether
you pre-read the file yourself or hand `dta_merge()` the path — the
convenience is free.

Against the context rows, `dta_merge()` from a file path at 1 GB (0.84--0.91 s)
is about 3 times faster than `base::merge()` on tables that are already in
memory, and in-memory `dta_merge()` (0.52 s) is about 5 times faster.
`dplyr::full_join()` on plain preloaded columns remains faster (0.40 s at
1 GB); it hashes plain doubles with none of the Stata semantics `dta_merge()`
implements, and the gap (~0.12 s at 1 GB) is the price of missing-identity
key matching, cast validation, and `_merge` construction on Stata-classed
columns.

Correctness across source combinations is covered by the package test suite:
`test-dta-merge.R` merges every pairing of {`.dta` path, `.arrow` path,
`read_dta()` memory, bare R vectors, mixed} for both sides — 25 combinations —
and asserts identical names, values, and missing-tag identity against the
in-memory reference.

## Reproduction

```sh
LIB=$(mktemp -d)/dtatools-lib
R CMD INSTALL --library="$LIB" r-package/dtatools
export DTATOOLS_BENCH_LIB="$LIB"
W=benchmarks/dta-merge/worker.R
Rscript --vanilla $W prepare \
    <master.dta> <master.arrow> <using.dta> <using.arrow>
Rscript --vanilla $W merge mem|path <x path> mem|path <y path> <iterations>
Rscript --vanilla $W competitor base|dplyr <x path> <y path> <iterations>
```

These are warm-cache measurements on one machine, not performance guarantees.
