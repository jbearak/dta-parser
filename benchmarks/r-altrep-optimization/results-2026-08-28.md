# R compact-vector optimization results (2026-08-28)

## Scope

This investigation covered numeric ALTREP serialization, base subsetting,
duplication, dictionary-string materialization, storage constructors, and
numeric recoding. Measurements used R 4.6.1 on arm64 macOS. The baseline was
`origin/main` at `6b5a07b`; the candidate was built from this branch. Both
packages used the same release-mode Rust build.

## Findings

The numeric ALTREP class had no serialization method. Serializing ten million
Stata bytes therefore materialized the source as doubles, wrote about 80 MB,
and restored an ordinary materialized vector. The custom state now copies the
one-byte backing into the serialized stream and records its storage metadata.
The source and restored vector remain unmaterialized.

| Ten-million-value serialization | Baseline | Candidate |
| --- | ---: | ---: |
| Serialized bytes | 80,000,184 | 10,000,302 |
| Elapsed seconds, one run | 0.089 | 0.002 |
| Source compact after serialization | no | yes |
| Restored compact | no | yes |

Base subsetting already avoided materializing the source, and vctrs re-encoded
the final result, but the generic ALTREP subset allocated widened intermediate
vectors. Duplication materialized both the source and copy. Native subset and
duplicate methods now copy values at their Stata width. In a one-million-value
profile, selecting half the values reduced profiled allocation from 67.7 MiB to
6.7 MiB including the 3.8 MiB integer subscript. Duplication fell from 15.3 MiB
to 1.9 MiB. Both sources and results remained compact.

Constructor validation allocated several full-length temporary vectors in R.
For one million `int` values, `Rprofmem()` recorded 124.0 MiB of allocations at
least 1 MiB each. Native validation and encoding reduced that to 1.9 MiB, the
final two-byte backing. This also removes those validation temporaries
when recoding restores compact storage. On ten million values, R's reported
maximum vector heap during a one-replacement recode fell from 740.0 MiB to
520.6 MiB. Elapsed time fell from 0.485 to 0.349 seconds in the same single-run
check.

Dictionary-string materialization did not show a useful target. Materializing
one million values drawn from 100 strings allocated 7.63 MiB in profiled R
vectors, which is the required one-million-pointer character result. The
temporary dictionary pointer table has only one entry per distinct string and
was below the 100 KiB profiling threshold. A compact subset result would require
cloning the native dictionary store, and the materialization profile does not
justify that added ownership path.

## Commands and checks

Packages were installed into separate temporary libraries, then exercised in
fresh `Rscript` processes. Serialization used `serialize(x, NULL, version = 3)`.
Allocation totals used `Rprofmem()` with a 1 MiB threshold for constructors and
100 KiB for focused operation profiles. Recode heap maxima came from the
`gc()` maximum-used counters printed by fresh worker processes.

Correctness is covered in `test-stata-numeric.R`: serialization and `saveRDS()`
round trips preserve values, attributes, storage type, and unmaterialized
backing; subset and duplicate tests include repeated and missing subscripts.
The exact commands are in this directory's README and the captured output is in
`raw-output-2026-08-28.txt`.
