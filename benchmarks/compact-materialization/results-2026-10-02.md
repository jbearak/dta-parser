# Compact materialization, 2026-10-02

Materializing an aliased compact column no longer copies its compact bytes
before decoding the doubles. At one million rows, this eliminates a 1 MB byte,
2 MB int, or 4 MB long/float copy. The required 8 MB double result remains.
In this fixed, heavily missing-bearing matrix, CPU improves by 1.03–1.18× for
those large aliased constructed columns. The clearest result is lower temporary
allocation, with a smaller CPU improvement than the comparison-kernel work.

Six balanced rounds produce 384 qualified observations using clean baseline
`fd72c344` and candidate `586b887b`. Both use the same separately compiled C
probe, which requests ordinary `DATAPTR_RO` exactly once per fresh compact
handle. No changed internal test helper is used for timing. Complete value bits,
all missing tags, alias independence and exact native copy counts pass; package,
probe and controller bindings stay unchanged. The complete
[observations](results-2026-10-02/timings/raw.csv),
[per-batch intervals](results-2026-10-02/timings/intervals.csv),
[summary](results-2026-10-02/timings/summary.csv) and
[independent audit](results-2026-10-02/validation/independent-audit.json)
retain the evidence.

## Results

Median CPU milliseconds per first materialization, including double allocation
and automatic collection. These are ratios of corresponding six-round medians.
MB here means one million bytes.

| Aliased constructed input, 1m rows | Before CPU ms | After CPU ms | CPU speedup | Removed compact copy | Rprofmem allocation before → after |
| --- | ---: | ---: | ---: | ---: | ---: |
| byte | 1.753 | 1.541 | 1.14× | 1 MB | 9,000,096 → 8,000,048 bytes |
| int | 1.635 | 1.594 | 1.03× | 2 MB | 10,000,096 → 8,000,048 bytes |
| long | 1.670 | 1.476 | 1.13× | 4 MB | 12,000,096 → 8,000,048 bytes |
| float | 1.728 | 1.470 | 1.18× | 4 MB | 12,000,096 → 8,000,048 bytes |

Wall-time speedups for those cases are 1.02–1.19×. At 4,096 rows, aliased
constructed int/long/float improve by 1.15×/1.30×/1.31× CPU; byte is essentially
unchanged at 0.99×. Across both sizes, private constructed and retained controls
range from 0.97× to 1.04× CPU. Their required allocation remains unchanged.
These controls already avoided the redundant compact copy.

The separate R vector-heap high-water observations fall by approximately the
same 1/2/4/4 MB for large aliased constructed columns. This metric and Rprofmem
allocation overlap; they must not be added. They are neither process RSS nor
process-wide peak memory, and they omit external allocator memory. The native
copy counter independently establishes the exact eliminated payload bytes.

## Ownership and correctness

The old materializer first detached shared compact backing by copying it, then
allocated and decoded a separate double vector. Decoding only needs a stable
read view. The candidate captures the original descriptor and its backing root,
temporarily claims that view across R allocations, and installs independently
owned materialized state on the target handle. Other aliases retain their
compact state and original values.

The claim matters because an allocation finalizer can mutate a private input.
Rooting its byte buffer alone preserves the address but does not preserve cached
facts such as the missing count. The temporary claim makes such mutation detach
instead of changing captured bytes in place. Reentry that replaces the target
state is detected and retried. Cleanup releases only its own unchanged claim,
preserving real sharing introduced by callbacks, and also runs on errors.

Regression tests cover metadata aliases, retained owners, target mutation after
materialization, exact missing tags, private zero-missing input patched to a
tagged missing during allocation, reentrant materialization, collection and
injected errors. The private checkpoint enters the materializer directly to
exercise callbacks normally suppressed by R's pointer-access guard. Separately,
the unchanged external pointer probe qualifies ordinary guarded access and
alias independence on both builds.

The clean installed candidate passes 51,968 full-suite assertions in 1,767 test
blocks, with no failures, errors or skips and seven existing warnings. Focused
materialization coverage passes 491 assertions; the broader ownership/mutation
regression selection passes 10,373 assertions. The benchmark controller passes
six tests with and without Python assertions enabled.

## Protocol and limits

The 32 cases cover 4,096 and 1,000,000 rows, byte/int/long/float storage,
constructed and retained backing, and private and metadata-aliased handles.
Every input repeats five exactly representable finite values followed by all
27 missing ranks: about 84% of rows are missing. This is an ownership and exact
decode fixture, not a representative missing-free ingestion workload. Retained
inputs use the immutable-owner test adapter with chunk lengths 257 or 8,191;
the experiment does not measure Arrow parsing or decompression.

Each build/round uses a fresh R process. Build order alternates and private/
aliased positions are balanced. Fixed batches contain at most 1,024 fresh
handles and roughly 64 MiB of compact-plus-double payload. Construction, full
region-read checks, explicit collection, profiling and destruction are outside
timing. Every timed handle and retained alias is checked bitwise before and
after the pointer request; no handle is timed after it is already materialized.

The run performs 4,452,155 first materializations in 7,753 batches. Individual
CPU and wall intervals span 6–26 ms, with no zero-duration intervals. Aggregates
span 150–165 ms CPU and 150–166 ms wall. The timer resolves roughly milliseconds;
summing short batches does not establish sub-millisecond interval precision.
All individual intervals are retained and their sums reproduce the aggregate
observations. No formal confidence interval is claimed.

Other local builds, tests and benchmarks were stopped during measurement. This
is one arm64 macOS host with R 4.6.1, without isolation from ordinary desktop
activity. The required decode and double-output allocation still dominate many
cases; removing this copy does not establish an R-wide or reader-wide speedup.
