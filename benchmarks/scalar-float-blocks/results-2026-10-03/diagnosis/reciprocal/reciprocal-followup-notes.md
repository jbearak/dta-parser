# Reciprocal residual, source and recorded compiler inspection

Scope: no runtime edit, build, new disassembly or performance measurement. The published final matrix remains unchanged. This inspection uses the already recorded clean f689 disassembly, with identical current general and float-scalar header bytes. It does not claim that instruction counts establish a time contribution.

The `1.01 / x` cases use native C loops. `arithmetic_general_source_create` reads the scalar once. Both integer-scalar and float-scalar proof admissions explicitly exclude a left scalar for division, and the compact-pair proof excludes scalar recycling. The operation therefore falls back to `arithmetic_general_run`.

Ranked diagnostic priorities:

1. General result and float-storage work is repeated on every row. `numeric-arithmetic-general.h:183-203` performs binary64 result validation, missing counting, valid-or-zero selection, a maximum-magnitude reduction, per-row safe-float-fit selection and narrowing. The typed-double loop in `numeric-arithmetic.h:230-234` retains only binary64 division, result validation, selection and missing count. Both use the same binary64 division precision. Eliminating the compact writer's output proof work where a whole-domain proof is available is the first experiment; its actual cost is not yet isolated.
2. Compact input conversion/classification adds work. The integer loop widens int16 through signed32 and signed64 into double, checks integer missing codes as double, substitutes R's NaN, and then reclassifies the computed result. The missing-capable float loop classifies raw tags/NaN/Inf in 32-bit lanes, inserts a quiet-NaN exponent, widens to double and reclassifies the result. The no-missing float source skips its encoded-missing classifier. This is distinct from failing to vectorize: the inspected integer and missing-capable float write loops each handle eight rows per SIMD iteration, have four `fdiv.2d` instructions, and no R callback in their vector bodies.
3. Integer storage preflight is additional work, but it is not automatically a second full-column pass. It returns after the first 16,384-row tile once a fractional result requires float/double. For this benchmark's int fixture, that first tile contains fractional results, so source flow predicts 16,384 preflight rows plus one million output rows. The inspected preflight uses scalar `fdiv`, `frintz`, minimum/maximum reductions and a fractional flag. Dynamic counters should confirm the path before its timing share is inferred.
4. Allocation, dispatch, tiled interrupt polling and promotion are whole-call costs. Current output checks show no promotion for these fixtures. The static loop inspection does not quantify their contribution; the compact destination is four bytes per row versus eight for typed doubles, so greater output traffic is not an explanation for this gap.

Recorded f689 addresses, all within `arithmetic_general_run`:

- Scalar / int16, float destination: dispatch `0x6a990 -> 0x6aaac -> 0x6acfc -> 0x70ca0 -> 0x7ffe4 -> 0x94158 -> 0xbce54`; vector loop `0xbced8..0xbcff0`, eight rows.
- Scalar / missing-capable float, float destination: `0x6acfc -> 0x6c470 -> 0x713e0 -> 0x805d4 -> 0x9487c -> 0xd9a0c`; vector loop `0xd9a5c..0xd9b94`, eight rows.
- Scalar / int16 preflight: `0x7fffc`, loop `0x80020` onward; scalar division and fractional testing.

A tight first diagnostic should count work at actual tile/producer entry boundaries, leaving the hot row loop untouched: preflight rows, output rows by producer/source/destination kind, generic-result-classifier rows, float-fit rows, and promotion-recompute rows. Confirm all four original reciprocal cases and controls through the public operation. Add lengths below/at/above 16,384, all-integer-result and first-fraction-late fixtures, zeros, missing codes and imported extrema. These are execution counts, not synthetic metadata classifiers.

The narrowest later production experiment is integer reciprocal proof after the existing storage preflight. For finite scalar and nonzero physical signed integer denominator, |scalar / x| <= |scalar|. If the scalar magnitude fits the chosen output's observed range, every nonzero result fits without an output range reduction. Existing captured missing_count plus the number of observed zero denominators gives the exact result missing count because integer missing codes and zero are disjoint. Preserve binary64 division and final narrowing, signed zeros, long's storage policy, source read claims and fallback for an unsafe scalar. This is a broad scalar-range/storage proof, not a special case for 1.01.

Float reciprocal needs a more complex two-interval input fit proof around zero, with observed infinities producing signed zero and inherited missing values preserved. A protected minimum-nonzero-magnitude block proof could be explored later. The existing p24/p24 direct-division proof does not apply to arbitrary binary64 scalar 1.01, which must remain binary64 here.
