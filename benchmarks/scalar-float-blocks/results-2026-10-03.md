# Scalar arithmetic on ordinary float blocks, 2026-10-03

The revised kernel is 1.627–1.759× faster on missing-free compact floats and
1.855–1.937× faster with sparse missings across the four targeted scalar
operations. These cases now approximately match or beat typed-double controls. Random dense
missings are essentially unchanged; dense cases still cost 1.822–1.900× as much
as typed doubles. These are direct gains against the accepted compact-pair
arithmetic baseline, not products of earlier speedups.

This experiment compares baseline
`dbcf75cbfe589b5ac2a78166d1e436faa7bbb896` with a block-proof candidate. The first
candidate, `9520f1105eb2556333642b9f591a6d3c9cf89bdc`, improved ordinary inputs but
regressed on dense missing values. The revision,
`2e512880b15ea5ef8d56c65a4916af3ad71fb928`, changes only how the writer stores its
immutable fit bounds and safe replacement value locally. Each revision must be
compared directly with the same baseline.

## Why a second candidate was necessary

The first 720-observation screen was numerically correct and failed the
performance requirement. Across addition, subtraction, multiplication and
column/scalar division, it improved missing-free input by 1.627 to 1.744 times,
sparse input by 1.768 to 1.852 times, and a 256-row missing prefix by 2.021 to
2.242 times. Random half-missing input had a 0.626 to 0.644 speedup, and all-tag
input had a 0.623 to 0.641 speedup. Values below one are slowdowns. Those dense
cases consumed roughly 56 to 60% more CPU, so the first candidate was rejected.

The [rejected screen](results-2026-10-03/rejected-screen/summary.csv) and its
[independent audit](results-2026-10-03/audits/rejected-screen.json) are preserved.
They are not relabeled as measurements of the revised candidate.

Disassembly of the exact installed libraries identifies a concrete difference.
The baseline's modern float addition loop with missing and fit checks uses
SIMD. The first candidate retained a SIMD ordinary loop but compiled the exact
fallback as scalar instructions. Clang reported 20 specializations where its
cost model declined vectorization. It did not report an illegal memory
dependence for this writer.

The revision copies the immutable lower bound, upper bound and replacement
value to local scalars before entering the writer loops. Bounds are read only
when fit checking is active, so explicit double output never reads the
uninitialized float-fit fields. This single source change removes the 20
cost-model refusals in the diagnostic compilation. The actual clean installed
library also contains SIMD exact classification, fit checks, replacement,
binary64 arithmetic and missing/promotion reductions.

The [compiler and DLL bindings](results-2026-10-03/validation/candidate-v2-codegen-binding.json)
separate this emitted-code observation from timing. The evidence supports a
compiler-sensitive loss of fallback vectorization. It does not assign an exact
share of the CPU regression to alias-check cost, repeated bound loads,
outlining or instruction-cache effects.

## What the native writer proves

The existing scalar kernel proves once that every finite binary32 input has a
valid binary64 result for the admitted operation. For float output, it also
finds a closed interval of binary32 inputs whose binary64 results fit the
storage policy. The scalar stays binary64, and the calculation keeps the
original binary64 expression before any output narrowing.

The new writer examines 64-row blocks. It reduces the maximum absolute
binary32 encoding and admits the simple loop only below Stata's first missing
encoding. When float-fit checking is active, the exactly widened positive and
negative maximum must both fit the existing interval. This conservatively
excludes encoded missing values, NaNs, infinities and high-magnitude imported
values. The exact fallback retains their existing classification and promotion
rules. It does not reinterpret every high imported value as missing.

After four consecutive failed block proofs, the writer uses its exact loop for
the remaining captured span. Each span is already bounded to 16,384 rows, so
proofs resume in the next span. A short missing prefix cannot select the exact
loop for an arbitrarily long column. The actual-writer structural regression
counted 1,000,000 classifications before the change and 16,384 afterward. The
test checks output values and bounded work, without a timing assertion.

Captured descriptors and backing claims, interrupt boundaries, missing counts,
whole-result promotion and private output publication remain unchanged.

## Measurement contract

The targeted panel has seven patterns and four public operations on one million
plain contiguous values: `x + 0.1`, `x - 0.1`, `x * 1.01`, and `x / 1.01`.
Each pattern has compact-float and typed-double representations. Missing-free
input also has a bare R control. There are 60 cases per build per round,
720 observations in six rounds, and 120 untimed qualification observations.

Sparse input contains 1,003 missing rows on a 997-row grid. Random-half and
clustered-half inputs each contain exactly 500,000. Prefix and suffix cases
contain 256, and all-tag input contains one million. All 27 canonical missing
ranks cycle where missing values occur. Finite values are exactly representable
in binary32. Cross-pattern comparisons do not isolate branch prediction.

Each build and round starts a fresh R process. Build order alternates. The
seven patterns rotate and reverse on even rounds; this does not cover all
permutations or give every pattern equal position counts. Operation order
reverses on even rounds. The two-representation cases alternate positions, and
missing-free cases use all six representation permutations. The requested
thread count is one.

Full hashes cover inputs, missing ranks, results, missing masks and metadata.
The independent oracle evaluates the original binary64 operation, then rounds
compact output to binary32 and verifies its storage policy. Typed-double and
bare results retain binary64 precision. Compact output bits therefore need not
equal typed-double output bits. Input/rank hashes agree across representations;
metadata stays stable within a case. Source ownership/materialization state,
result storage and missing caches are checked. Actual scalar-entry counters
must equal every timed native call, and remain zero for bare R.

Repeated public calls include result allocation and automatic garbage
collection. Construction, explicit collection, calibration, hashes and
qualification are outside the interval. Calibration targets repeated intervals
of about 300 ms CPU. Before and after each panel, the controller binds the
absolute Rscript launcher and actual runtime, original build receipts, source
and installed-library inventories, and controller/helper files. The audit
recomputes worker/raw identities, orders, medians and paired ratios.

## Test-only review follow-up

Commit `2cb76c06e91cd5129ef9497a9b28ed08fe809eeb` adds a public mutation check
to both new scalar block test families: clear every decoded missing row, then
require the cached `anyNA` result to become false. This can catch a stale surplus
count that an initial boolean check would miss. The change affects only that
test file and its manifest; R and native runtime sources are byte-identical to
the measured candidate.

The expanded focused suite passes 31,442 assertions, with no failures, errors,
skips or warnings, against both the measured `2e512880` library and the separate
combined `7003eba9` library. The two manifest minima increase from 1,458 to 1,566
and from 1,931 to 2,061; seven manifest guards pass. The
[post-run identity binding and exact scope](review-mutation-2026-10-03/binding.json)
records the committed test source, installed-library identities, commands and
focused observations. It does not relabel the original benchmark, full-suite
or source-archive results as runs of the changed tests. Final-head CI exercises
the updated suite.

Published text copies substitute private paths and remove direct USER/LOGNAME
values and their direct hashes. Historical completion, audit and build records
retain their original whole-artifact hashes; those hashes refer to the original
private artifacts, not redacted copies. The publication source map records both
original and published hashes, and the publication manifest binds the public
copies. Scripts with path placeholders require local path restoration before
replay. Objects, libraries, fixture binaries and source archives stay in the
private evidence store.

These observations concern warm constructed operations on one host. The
targeted screen excludes reverse division; the broader panel retains it as an
unchanged control. Neither panel measures reader throughput, retained-layout
throughput, temporal columns or arbitrary imported representations.
