# Long and float addition without repeated missing classification

Both 696-observation screens and their independent audits passed. The later
combined source archive also passed required conformance.

Plain long/float addition now uses approximately the same CPU as typed-double
addition for ordinary inputs. Sparse inputs improve 1.43 to 1.45 times, with
an 18.6% to 20.0% typed-double CPU gap remaining. Fully missing inputs improve
2.75 to 3.01 times. Dense mixed missing inputs and very short retained chunks
still have material costs; this result does not establish universal parity.

The change applies to full-length, non-temporal Stata long/float addition in
both operand orders. The result remains binary64. It preserves integer values
such as 16,777,217 exactly and keeps the existing missing-value, import and
copy-on-write semantics.

## Mechanism

A 64-row proof reduces the signed maximum of long values and the unsigned
maximum of absolute float bits. Values below the relevant long missing code
and below the first float missing range are observed and finite. Their output
is the original source-order binary64 addition, with no per-value missing
classification or count update. A signed long maximum admits INT32_MIN.
The conservative float bound leaves noncanonical high finite imports to the
existing exact writer rather than treating them as missing.

Exceptions retain that exact format-aware writer, including the union of
missing positions. Inherited counts cannot be summed because positions may
overlap. Four failed block proofs use the exact writer for the remainder of
the current captured span, at most 16,384 rows. Proofs resume on the next span.
This bounds the penalty of a dense prefix.

A second proof uses the captured exact missing count. If either complete
native input is missing, every sum is system missing. The new fill writes
canonical double NA without requesting input spans or decoding either input.
It increments the output count once per output tile and polls interrupts at
most 16,384 rows apart. Admission stays inside this long/float addition route.
The reusable double-fill helper introduces no other producer admission.

The arithmetic entry captures both native descriptors and their backing before
output allocation. Plain compact read claims force supported reentrant writes
to detach; retained inputs use a private rooted owner. The all-missing fact is
read from those stable captured descriptors, never from a later public handle.

## Evidence before the final screen

The first source 387227 screen contains 696 observations from 26 operation cases,
both operand orders, compact/typed controls and ordinary-input bare controls.
Plain ordinary addition improved 1.215–1.225 times and used 1.001–1.044 times the
typed-double CPU. Plain sparse addition improved 1.468–1.471 times, reaching
1.131–1.178 times typed CPU. Prefix/suffix gains were 1.625–1.721 times.

It also exposed limits. Random dense missing throughput was essentially
unchanged, and one plain all-tags order had a 5.8% ratio-of-medians CPU cost,
3.4% by paired rounds. Short 7/11 retained spans remained 36.7–41.1 times the
plain typed controls. This last contrast intentionally changes storage geometry;
it does not attribute the cost to one component. Poll cadence and repeated
region lookups are separate follow-ups and are excluded from this change.

The all-missing follow-up was tested structurally before implementation. The
actual-header probe keeps 130 previous cases and adds 32 all-missing cases across
both operand orders, plain/retained/short geometry and both missing layouts.
The unchanged source passes all 162 value/count cases but fails 58 work gates,
including earlier small cases whose complete input is missing. The narrow fill
passes all 162 cases and removes all source-span, proof and exact-loader work
from those 58 cases. Each million-row fill retains 62 interrupt polls. Those are
structural counts from private copies of the actual headers with mocked R
boundaries, not timings or public ownership evidence.

A receipt-bound installed-DLL extraction shows the new fill uses a vector
broadcast and paired 128-bit stores, writing eight doubles per loop iteration.
The output pointer and NA value load once per tile, not per lane. The ordinary
addition writer and exact fallback were already vectorized in the earlier
candidate; the optimization removes repeated work rather than claiming that
baseline arithmetic was scalar.

## Final measured result

The final frozen 3de25 screen compares directly with 7003. Its 696 observations,
116 no-clock qualifications, complete values, state, cache checks and source
bindings passed independent audit. Gains below are baseline CPU divided by
candidate CPU, using medians of six rounds. They are not products of stage gains.

| Input and geometry | CPU speedup | Candidate CPU / typed double |
| --- | ---: | ---: |
| Plain, ordinary | 1.210 to 1.253 | 0.997 to 1.003 |
| Plain, sparse missing | 1.431 to 1.454 | 1.186 to 1.200 |
| Plain, 256-row missing prefix/suffix | 1.665 to 1.817 | 0.967 to 1.050 |
| Plain, independent half-missing inputs | 0.991 to 1.023 | 1.681 to 1.708 |
| Plain, all tags | 2.750 to 3.011 | 0.582 to 0.591 |
| Retained 8191/16385, ordinary | 1.150 to 1.156 | 1.106 to 1.132 |
| Retained 8191/16385, sparse missing | 1.343 to 1.429 | 1.202 to 1.214 |
| Retained 8191/16385, missing prefix/suffix | 1.410 to 1.553 | 1.095 to 1.124 |
| Retained 8191/16385, independent half-missing inputs | 0.904 to 0.919 | 1.752 to 1.762 |
| Retained 7/11, ordinary/sparse | 0.889 to 0.986 | 36.670 to 41.550 |

Wall-time speedups are similar in this single-threaded screen. The full summary
also retains paired-round ratios. All-tags paired CPU gains are 2.740 to 2.883.
The plain ordinary result remains 1.196 to 1.219 times bare-double CPU, so parity
here refers to the typed-double control, which preserves package semantics.

The retained dense and short cases regressed in this run. Typed-control speedups
also range from 0.858 to 1.101, and bare-control speedups from 0.944 to 1.023.
Dividing paired compact cost by paired typed-control cost leaves a 6.2% residual
cost for retained dense long-plus-float and 1.7% for the opposite order. The same
normalized short-case ratios range from 0.968 to 1.040. These controls help
describe shared shifts; they do not explain away the remaining cost.

The final and previous installed DLLs have the same 1,260 exact-fallback helper
instructions after normalizing internal branch targets and resolved page
addresses. SIMD classification and addition remain, with no new per-lane loads
in that helper. This rules out lost fallback vectorization between these two
candidates. It does not prove equality of caller layout or identify the cause
of the timing residual. Both original screens remain published; no replacement
run was used to average away a negative observation.

## Protocol and source limits

The final matrix keeps 58 observations per build and round, 116 no-clock
qualifications and 696 observations across six rounds. Plain uses six patterns;
retained 8191/16385 uses all except all-tags; short 7/11 uses ordinary/sparse.
Both input random masks are exactly half missing and independently randomized,
so result missing density is their recorded union, approximately 75%.
Typed and bare controls stay plain doubles in retained panels. Inputs are
constructed modern compact columns; import and temporal throughput are outside
this screen.

Timing covers repeated public calls, output allocation and automatic GC.
Construction, calibration, explicit GC, full hashing and mutation checks are
outside the clocks. A final result is checked in full after each interval.
Every native result is then aliased through a dibble and all expected-missing
rows are cleared. Full cleared bits, a false anyNA result, unchanged original
output and unchanged sources verify the missing cache and copy-on-write.
The final recorded CPU intervals range from 152 to 412 milliseconds.

Source/result value hashes agree across equivalent layouts, orders and
representations. Metadata hashes are stable within each case; compact and typed
classes are not claimed equal. Build and representation orders are balanced;
pattern/layout rotations and reversals are recorded without an exhaustive
permutation claim. Exact runtime, source, library, controller and qualification
bindings are checked before and after each stage.
