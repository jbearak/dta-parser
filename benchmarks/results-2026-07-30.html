The work added two report-only systems: a reproducible same-run R performance benchmark and a manual, bounded, resumable differential corpus framework. Neither adds timing assertions or private-corpus checks to CI.

What changed and why

  1. Reproducible R benchmark harness. Added deterministic 100 MB and 1 GB release-118 inputs, checkout-local package installation, strict build and run provenance, atomic publication, and a strict summarizer. Why: performance comparisons are only useful when the measured checkout, input identities, matrix shape, and methodology are auditable.
  2. Three-reader same-run comparison. Benchmarked public Direct-R, retained Rust vectors, and Haven in one run, with warmups, alternating order, and garbage collection outside timing. Why: this separates parser/materialization changes from machine or run-to-run effects and connects current public behavior to the historical Rust-vector baseline.
  3. Manual fertility-corpus framework. Added deterministic inventory, exact metadata/value comparison, isolated workers, bounded row/column tiling, timeouts, memory limits, resumable checkpoints, sharding, strict merges, and privacy-safe reports. Why: tens of gigabytes of proprietary survey files provide practical robustness coverage that small public fixtures cannot, but must remain machine-local and nonautomatic.
  4. Explicit source authorization. Raw runs now require canonical --cache-root and --manifest; generated-output runs require --output-root. The framework refuses CI and symlinked or ambiguous roots. Why: private inputs must never be inferred, recursively discovered, or accidentally read on an unauthorized machine.
  5. Exact comparison semantics. Replaced broad equality shortcuts with element- and attribute-level checks for dimensions, names, metadata, classes, labels, missing masks, tagged missings, dates, datetimes, strings, integers, nonfinite values, and finite floating values with absolute tolerance 1e-7. Why: a corpus pass should prove compatibility rather than hide meaningful differences behind permissive coercion.
  6. Crash and race hardening. Added per-tile subprocesses, process-generation locks, heartbeats, descriptor-bound input snapshots, no-follow directory traversal, input revalidation, atomic no-replace publication, and exact bundle membership validation. Why: very long runs must survive interruption without accepting stale, mixed, partially published, or path-substituted evidence.
  7. External input-identity separation. Preserved five disagreements between caller-supplied manifest hashes and current bytes while recording separately authorized target-local evidence. Why: maintaining the external hash records is outside this repository's responsibility, but the harness must not silently treat different bytes as manifest-verified.
  8. Generated-output support. Reused the Wave 2 machinery for 1,226 derived files, including very large top-level aggregates and upstream append, force output. Why: reader parity must be distinguished from analytical coercion already stored in the generated Stata files.
  9. Privacy-safe documentation. Added dated Markdown reports and this consolidated HTML report while removing local absolute paths, source hashes, survey values, labels, variable names, and private reader diagnostics. Why: methodology and aggregate conclusions should be reviewable without disclosing proprietary corpus details.

Why Haven is used as an oracle

Haven is the established R Stata reader and dtaparser::read_dta() deliberately targets its public R API and object semantics. Agreement is strong compatibility evidence, but not proof of universal correctness. Every disagreement is also checked against Direct-R/Rust-vector identity, Stata storage semantics, structural validation, checked fixtures, and targeted synthetic reproductions. Haven can itself differ around malformed UTF-8, undeclared legacy encodings, modern strL overrides, or native coercion boundaries.

Caveat: these are warm-cache, machine- and workload-specific measurements, not API promises or release thresholds.
