# Final combined original-operation acceptance

This retains the original combined7003 general-worker operation selection and input formulas. The measurement worker is unchanged from the independently audited integer-reciprocal acceptance panel. Controller experiment text and final candidate identity are updated separately; a launch guard requires the same build, runtime and controller identities as the completed untimed qualification. No package code is changed by this benchmark.

There are 34 width/missing/operation cases, three representations, two builds and six rounds: 102 worker records per build/round and 1,224 retained observations. Int16 and float each run the original seven general operations; int16 adds mixed float addition/multiplication; long runs only the original long+float addition. This is the accumulated accepted follow-up comparison against an earlier integration that already contains native kernels. The typed-double and ordinary-double implementations are controls. This panel does not measure dense or retained layouts, readers or universal compact parity.

The x input is `as.double((seq_len(1000000) * 13) %% 10001 - 5000)`, divided by eight only for float. The y input is `as.double((seq_len(1000000) * 19) %% 1001 - 500)/8`. Sparse missing starts at row 13 with stride 997 in x and row 19 with stride 991 in y. Typed values use the original independent Stata normalization, storage, promotion and float-rounding oracle. Bare results use ordinary R arithmetic, including its own Inf/NaN behavior.

Every typed retained result is qualified after the clocks and native-entry counter deltas. The worker clears all oracle-missing rows through a dibble alias and `replace_values`, compares the complete cleared bits, requires no remaining missing values, and rechecks the original result and both input hashes/states. No-missing results still receive complete-bit and missing-cache checks. Ordinary controls have no native cached count and record no mutation probe. The controller enforces `mutation_checked` and `cleared_sha256` and compares them across builds/rounds.

Warmup, explicit GC, calibration, hashing and mutation qualification are outside retained intervals. Result allocation and automatic GC remain inside. The original 25 ms calibration minimum and 150 ms target are unchanged; actual intervals are recorded. Build order alternates; case order is fixed; the original rotate/reverse formula balances all six representation orders. Both typed builds must use the native arithmetic entry on every timed call.

The baseline is `7003eba901671797ee91fffc97f08e28a1f7f515`, using its existing qualified clean build. The final combined candidate is `3eadb244253fb817d5773b01b11cb36c284f3a1d`, using its separately qualified clean build. Both builder receipts use `baseline` mode to mean an immutable unpatched Git export; benchmark roles remain baseline and candidate. The recorder comes from the frozen combined7003 checkout.

Run the normal and optimized Python guards, then the two 102-case untimed qualifications. Start the paired timing only with the completed qualification and an exclusive local timing window. The independent audit verifies every case, result/source identity, statistic, build/runtime/controller binding and the qualification-to-timing link. All observations and costs are retained; gains from separately measured stages are not multiplied.
