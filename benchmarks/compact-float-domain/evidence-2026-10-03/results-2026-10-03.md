# A protected compact-float domain fact

The corrected candidate is accepted with the measured tradeoffs below. Both
840-observation stages passed independent semantic and source-binding audits.
The final combined source passed its required archived package suite and the
separate original 34-case, 1,224-observation acceptance panel.

Modern Stata float missing values occupy 27 exact high finite bit patterns.
For a buffer restricted to the observed Stata float range and those patterns,
one float comparison identifies a missing value. Permissive imports can also
contain high finite gaps, infinities and IEEE NaNs, so the same shortcut is not
valid for every compact float buffer.

The change records that restricted domain in an initialized internal descriptor
flag. Generic construction, import, unserialization and adoption start UNKNOWN.
The fully validating public constructor opts in after its encoding pass.
Supported writable access invalidates the fact before exposing mutable bytes.
Arithmetic reads the fact from the same captured descriptor and protected
backing claim that supplies the values and exact missing count. A later patch
or materialization of the public handle cannot change those captured inputs.

The test-only retained-buffer freeze independently validates its copied bytes.
It captures and protects its source before allocations or callbacks, and its
cleanup releases only the claim it installed. Public results do not acquire a
new fact merely because this arithmetic writer produced them. Reader adoption
also remains UNKNOWN.

The only new production consumer is non-temporal, full-length LONG plus FLOAT
addition with a DOUBLE result, in either operand order. The existing binary64
expression and exact missing union remain unchanged. A captured all-missing
source still takes the existing system-NA fill. UNKNOWN inputs retain their
exact modern or legacy loader.

## Rejected whole-span policy

The first public candidate, `452ac723`, applied the simplified missing-union
writer to an entire captured span whenever the fact was known. All 840
observations passed their semantic and provenance checks, but that policy was
rejected. Dense constructed inputs improved 1.365–1.456×, while plain ordinary
inputs slowed to 0.940–0.952× baseline speed and plain prefix/suffix cases to
0.840–0.890×. The new route unnecessarily performed per-row missing-union work
that the existing ordinary block proof had already eliminated.

Those source, build, timing, audit and rejection records remain unchanged.
The UNKNOWN imported-input panel was measured separately and did not establish
a benefit from the new fact.

## Corrected exception policy

Candidate `19f57372` restores the existing 64-row ordinary proof and observed
writer. It uses the strict-domain loader only at the two existing exception
sites: a failed block and the bounded exact remainder after four failed blocks.
No density threshold, new lifetime rule or descriptor change was added by this
correction. A captured span still bounds the period before proofs resume.

A separate actual-header work test rejected the whole-span candidate with
14 work failures and zero semantic failures across 162 cases. The corrected
candidate passes the same matrix. On million-row plain fixtures, canonical
writer rows fall from one million to zero for ordinary inputs, 124,160 for
sparse inputs, 16,384 for a 256-row missing prefix and 256 for a missing suffix.
The trusted route performs zero generic float classifications. Dense inputs
still use the canonical exception writer, and all-missing inputs read no input
spans. These are source-level work counts, not elapsed-time or ownership tests.

The first draft of the new private controller accidentally added retained
suffix cases to its expected matrix without adding them to the C driver. Its
validation rejected that mismatch. The failed draft and records are preserved;
the inherited 162-case matrix was restored before the red and green runs.

All 840 corrected observations completed. Independent raw-interval replay
reproduces all 32 summary rows. Dense strict inputs improve 1.338–1.641× by
median CPU, or 1.335–1.560× by paired-round speed. Their compact/typed CPU ratio
is 1.070–1.258. The paired compact cost divided by the paired typed-control cost
is 0.683–0.726, so the dense improvement remains visible after that control
comparison.

Plain ordinary speed is 0.986–1.028× baseline and its compact/typed ratio is
0.979–0.981. The large prefix/suffix costs of the rejected whole-span policy
are gone. This does not establish zero regression: retained suffix LONG+FLOAT
has 0.961× direct speed, 0.972× paired speed and a 1.067 paired cost after typed
control normalization, with higher normalized cost in five of six rounds.
Short ordinary FLOAT+LONG has 0.961× direct speed and a 1.052 normalized cost,
with higher normalized cost in all six rounds. Short-chunk compact results remain roughly 38–40× typed
CPU in this isolated comparison, which predates the independently measured
polling and locator changes.

UNKNOWN sparse LONG+FLOAT has 0.938× direct speed and 0.935× paired speed, but
its normalized cost is 0.995. UNKNOWN random FLOAT+LONG retains a 1.035
normalized cost, higher in four of six rounds. These controls remain on the exact loader and receive no
strict-domain admission. Typed-control speed varies from 0.898 to 1.167 across
the complete experiment. In particular, the unchanged all-missing fill shows
1.144–1.193× direct speed but 0.984–0.998 normalized cost; that apparent gain is
not attributed to the new domain fact. Neither the observed shifts nor the
remaining small costs establish a particular host or compiler cause.

Retained CPU intervals are 190–390 ms in the strict panel and 200–390 ms in the
UNKNOWN panel. No claim of universal parity is made.

## Qualification and benchmark scope

The isolated measured comparison is exact baseline `213ceeee` against corrected
candidate `19f57372`. Both libraries come from clean immutable source exports.
The earlier rejected comparison uses the same baseline and candidate `452ac723`.

The strict panel contains 696 observations over six balanced rounds, one
million rows, both operand orders, and compact, typed-double and missing-free
bare controls. It covers plain, retained 8,191/16,385-row chunks and short
7/11-row chunks, with ordinary, sparse, random-half, prefix, suffix and
all-tag cases where specified by the complete protocol. Typed and bare controls
remain plain; they are repeated within each layout panel. Independent input
masks mean the output missing density is the recorded union, not simply 50%.

The separate UNKNOWN panel contains 144 observations over ordinary, sparse
and random-half imported inputs. It uses immutable modern DTA files read
outside the clocks. Fixture production is bound to the baseline DLL and exact
R runtime, and the worker independently regenerates the expected grids and
missing ranks. The old baseline explicitly lacks the new proof diagnostic.
The candidate must report TRUE for strict compact constructor/freeze inputs
and FALSE for imported inputs.

Both panels bind full input, rank, result and missing hashes across equivalent
representations and layouts. Metadata stays stable within each corresponding
representation and layout. They check result storage, captured source state,
native entry counts, and public clearing of every missing result outside the
clock. Source, library, controller, fixture and exact R launcher/runtime
identities are bound before and after the run. Repeated public calls include
result allocation and automatic GC; preparation, explicit GC, calibration,
hashing and qualification are outside retained intervals.

Before corrected timing, all 140 no-clock observations passed independent
audit. The corrected clean library passed 34,602 focused assertions in 42
blocks, including public cache mutation and reentry cases. The unchanged
lifecycle/layout implementation had previously passed the rejected candidate's
complete installed suite of 106,731 assertions in 1,823
blocks, with no failures or skips and seven existing warnings. This historical
full-suite result is not attributed to the corrected source.

Final combined source `3eadb244` integrates the separately accepted polling,
uniform-chunk locator and adaptive reciprocal changes. Its clean library passed
38,954 focused assertions in 47 blocks. The required retained-archive suite
passed 111,083 assertions with zero failures or skips and seven existing
warnings. The source binder verifies 354 packaged implementation, R, test and
manifest files against immutable Git blobs, with 20 explicit build exclusions.
The same integration passed 71 Rust tests, 16 guard commands and the four
current-header structural matrices. The Rust launch description is an explicit
post-run supplement. These integration checks do not reattribute either
isolated timing stage to the combined source.

Actual corrected DLL extraction and a separately bound same-release-flags
diagnostic object show vectorized ordinary proofs, observed output, all four
canonical writer instantiations and all six UNKNOWN exact instantiations.
Independent replay verified the source, compiler, object and installed DLL
bindings. This establishes code generation on the tested toolchain, not a
cross-compiler guarantee or a timing result.

The separate final 34-case panel compares qualified integration `7003eba9` with
combined source `3eadb244`. It contains 1,224 observations after 204 untimed
qualifications. Compact CPU is 0.769–1.545× typed-double CPU and 0.778–1.915× bare
double CPU. LONG/FLOAT addition improves 1.182× for ordinary inputs and 1.452×
for sparse missing inputs against that earlier integration. These are accumulated
follow-up results, not an isolated estimate of the new domain fact. Costs and
control movement remain in the complete table and per-round records.
