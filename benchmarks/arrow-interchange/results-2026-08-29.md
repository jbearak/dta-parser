# Arrow interchange benchmark results

Run date: 2026-08-29.

Environment: Apple M4 Max, 128 GB RAM, macOS 26.5.0, R 4.6.1,
dtatools 0.6.0 (development), Haven 2.5.5. The write matrices and conversion
costs were originally measured with the package built from commit
`b2e27d5ca360171efdd690aaea5b92fe0ea2999a` on the
`docs-arrow-ipc-interchange-format` branch and installed into a private
benchmark library; the read comparison was remeasured the same day after the
multicore `read_arrow()` revision that followed that commit, and the
`save_arrow()` figures were remeasured again the same day after the write-path
optimizations through commit `2bc55c3` (see the additive-impact section
below). Stata medians are reused from the primary matrix in
`benchmarks/large-scale/results-2026-08-28.md`, measured earlier on the same
machine; Stata was not rerun.

`benchmarks/arrow-interchange/worker.R` performs one operation per invocation.
Read tasks run warm in one process: one untimed warm read, then timed
iterations with a full garbage collection between them. Write tasks follow the
large-scale write methodology: every iteration is a fresh R process that first
constructs or reads the input, garbage-collects, and then times only the save
call. All values below are medians; this run recorded times only, not
percentiles, peak RSS, or provenance bundles. File sizes use decimal MB and
GB.

## Read comparison

Synthetic reads used the canonical large-scale fixtures
(`target/large-scale/datasets.tsv`, creator `stata-first-save`): 231,956 and
2,320,123 rows across 40 columns. The India 2021 DHS women's file is 5.20 GB
with 724,115 rows and 5,972 columns. The corresponding `.arrow` files were
produced by `save_arrow()` from the `read_dta()` read model of each file.
Synthetic reads ran 11 timed iterations; India reads ran 5.

| Input | `read_dta()` | `read_arrow(verify = TRUE)` | `read_arrow(verify = FALSE)` |
| --- | ---: | ---: | ---: |
| Synthetic 100 MB | 0.048 s | 0.028 s | 0.026 s |
| Synthetic 1 GB | 0.184 s | 0.097 s | 0.092 s |
| India 2021 DHS women | 1.608 s | 0.416 s | 0.403 s |

Both readers decode with automatic multicore workers and defer numeric and
character materialization through ALTREP. `read_arrow()` is faster because
the Arrow file already stores each column contiguously in its declared Stata
storage width, so a read is mostly parallel column copies rather than
row-major decoding; checksum verification adds roughly 3--6%. Both functions
return the same read model — `identical()` holds between the `read_dta()` and
`read_arrow()` results on the synthetic fixtures — and the Arrow round trip
is bit-exact against the DTA round trip in the package test suite.

An earlier single-threaded `read_arrow()` prototype that materialized string
columns eagerly measured 0.296 s / 1.448 s / 4.423 s with verification on the
same three inputs earlier the same day; the table above reflects the revision
that parallelized record-batch decoding, checksum verification, and column
conversion, and deferred null-free string columns through the dictionary
ALTREP class.

The India `read_dta()` median here (1.608 s over 5 iterations) is consistent
with the published corpus figure of 1.9 s measured over more iterations on an
earlier commit.

## Arrow conversion cost and file sizes

`save_arrow()` timings for producing each `.arrow` benchmark file from the
in-memory `read_dta()` result, single fresh process each:

| Input | `save_arrow()` | DTA size | Arrow size |
| --- | ---: | ---: | ---: |
| Synthetic 100 MB | 0.037 s | 100.000 MB | 101.574 MB |
| Synthetic 1 GB | 0.254 s | 1.000 GB | 1.016 GB |
| India 2021 DHS women | 1.367 s | 5.196 GB | 5.560 GB |

The Arrow files are uncompressed IPC with per-buffer xxHash64 checksums, so
they run slightly larger than the DTA originals.

## Primary write matrix (Stata-class inputs)

Same design as the large-scale primary matrix: each fresh process reads
Stata's first-save fixture with `read_dta()` and times one writer. Seven
iterations per writer per scale. `save_dta()` used `version = 19L` and
`haven::write_dta()` used `version = 15L`, matching the published runs.
`save_arrow()` writes Arrow IPC rather than DTA, so its output is a different
format produced from the identical input.

| Writer | 100 MB median | 100 MB output | 1 GB median | 1 GB output |
| --- | ---: | ---: | ---: | ---: |
| Stata `save` (reused) | 0.013 s | 100.000 MB | 0.130 s | 1.000 GB |
| `save_dta()` | 0.023 s | 93.969 MB | 0.152 s | 0.940 GB |
| `save_arrow()` | 0.037 s | 101.574 MB | 0.254 s | 1.016 GB |
| `save_arrow(checksums = FALSE)` | 0.031 s | 101.569 MB | 0.235 s | 1.016 GB |
| `haven::write_dta()` | 1.238 s | 118.093 MB | 9.048 s | 1.181 GB |

The rerun `save_dta()` and Haven medians reproduce the published 2026-08-29
primary matrix (0.023/0.150 and 1.235/9.045) within normal variation, so the
`save_arrow()` column is directly comparable. On these inputs Haven took
53.8 times `save_dta()`'s median at 100 MB and 59.5 times at 1 GB.
`save_arrow()` sits within 1.6--1.7 times `save_dta()`: after the write-path
optimizations below, compact ALTREP columns and dictionary strings export
without copies or materialization. The checksums account for only the small
step to the `checksums = FALSE` row — hashing runs on worker threads that
overlap the write — so the remaining gap to `save_dta()` is mostly the 8%
larger output and the Arrow IPC framing pass. Before these optimizations the
default row measured 0.424 s and 1.862 s.

## Secondary write matrix (ordinary R inputs)

Same design as the large-scale secondary matrix: each fresh process builds the
40-column ordinary R data frame from
`benchmarks/large-scale/standard-r-write-fixture.R` (222,711 rows at 100 MB,
2,227,111 rows at 1 GB) and times one writer. Seven iterations per writer per
scale.

| Writer | 100 MB median | 100 MB output | 1 GB median | 1 GB output |
| --- | ---: | ---: | ---: | ---: |
| `save_dta()` | 0.193 s | 97.128 MB | 1.927 s | 0.971 GB |
| `save_arrow()` | 0.105 s | 101.857 MB | 0.897 s | 1.018 GB |
| `save_arrow(checksums = FALSE)` | 0.102 s | 101.852 MB | 0.892 s | 1.018 GB |
| `haven::write_dta()` | 0.495 s | 99.801 MB | 4.195 s | 0.998 GB |

The rerun `save_dta()` and Haven medians again track the published secondary
matrix (0.183/1.797 and 0.439/4.052). On ordinary R columns `save_arrow()` is
the fastest writer: 45.6% faster than `save_dta()` at 100 MB and 53.5% faster
at 1 GB, and roughly 4.7 times faster than Haven. Without Stata storage
declarations there are no compact columns for the DTA fast path to exploit,
and the Arrow writer skips DTA-specific work such as fixed-width string
planning.

## Write-path optimization: additive impact

The `save_arrow()` figures above reflect five optimizations applied in
sequence, each committed separately and benchmarked with the identical
harness (seven fresh-process iterations for the write matrices, three for the
India conversion). Every stage produced byte-identical output files — the
SHA-256 of each output matched across all six checksummed builds for every
task and scale — so the stages differ only in speed:

1. **dictstring** — unmaterialized dictionary-string ALTREP columns (the form
   `read_dta()` returns) export directly from their dictionary views instead
   of materializing every CHARSXP.
2. **parallel-encode** — column-to-Arrow conversion runs on a worker pool,
   with R-API extraction kept on the main thread; `save_arrow()` gained a
   `threads` argument (default automatic).
3. **parallel-hash** — the per-batch, per-column xxHash64 checksums are
   precomputed on a worker pool before the serial IPC writer loop.
4. **zero-copy** — columns whose Arrow bytes equal the R backing (payload
   doubles, NA-free doubles and integers, raw, and compact Stata numerics
   from modern format versions) wrap R memory directly instead of copying.
5. **overlap** — checksum hashing runs concurrently with the batch-write
   loop instead of completing before it, since the checksums document is
   only needed for the footer.

The final column, **no-checksums**, is not a stage but the overlap build run
with `checksums = FALSE`; its outputs omit the footer checksums document (a
0.03% size difference at most) and are the one column whose bytes differ.

Medians in seconds:

| Task | Scale | baseline | dictstring | parallel-encode | parallel-hash | zero-copy | overlap | no-checksums |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Primary write | 100 MB | 0.430 | 0.053 | 0.034 | 0.034 | 0.034 | 0.037 | 0.031 |
| Primary write | 1 GB | 1.886 | 0.439 | 0.241 | 0.244 | 0.247 | 0.254 | 0.235 |
| Secondary write | 100 MB | 0.122 | 0.116 | 0.106 | 0.107 | 0.104 | 0.105 | 0.102 |
| Secondary write | 1 GB | 1.048 | 1.041 | 0.912 | 0.911 | 0.906 | 0.897 | 0.892 |
| India conversion | 5.2 GB | 6.385 | 5.351 | 1.918 | 1.798 | 1.371 | 1.367 | 1.327 |

String materialization dominated the primary (Stata-class) writes, so the
dictstring stage alone cut them 4--8 times; parallelizing the encode roughly
halved the remainder. The secondary inputs hold no dictionary strings and
their eager string conversion is inherently main-thread R API work, so those
writes improve more modestly. The wide India file gains from every stage
through zero-copy (1.798 s to 1.371 s), because its nearly 6,000 compact
numeric columns previously paid one copy each. The overlap stage and the
`checksums = FALSE` column bound the residual cost of checksumming: once
hashing is parallel it is already close to hidden, and disabling it entirely
recovers only 1--8% depending on shape. The baseline medians here
(0.430/1.886, 0.122/1.048, 6.385) reproduce the originally published figures
(0.424/1.862, 0.126/1.033, 6.529) within normal variation.

## Reproduction

```sh
LIB=$(mktemp -d)/dtatools-lib
R CMD INSTALL --library="$LIB" r-package/dtatools
export DTATOOLS_BENCH_LIB="$LIB"
W=benchmarks/arrow-interchange/worker.R
Rscript --vanilla $W prepare-arrow <input.dta> <output.arrow> [nochecksums]
Rscript --vanilla $W read-dta <path.dta> <iterations>
Rscript --vanilla $W read-arrow <path.arrow> <iterations> verify|noverify
Rscript --vanilla $W write-primary \
    save_dta|save_arrow|save_arrow_nochecksums|haven <input.dta> <output>
Rscript --vanilla $W write-secondary \
    save_dta|save_arrow|save_arrow_nochecksums|haven \
    benchmarks/large-scale/standard-r-write-fixture.R <rows> <output>
```

These are warm-cache measurements on one machine, not performance guarantees.
