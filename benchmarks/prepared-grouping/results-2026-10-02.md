# Numeric grouping: prepare keys before sorting

Across 20 constructed-input cases, compact `dta_group_id()` is **11.94–23.69×
faster in CPU time** than the accepted baseline. Its CPU is **0.967–1.007× typed-double**
and **0.961–1.003× ordinary-double** CPU in the candidate. This measured matrix
reaches double-control throughput while keeping source columns compact.
The tradeoff is an additional **eight bytes per row per numeric key** until
grouping finishes.

These results cover 100,000 rows with one or four byte, int, long or float
keys, plus one-million-row single-key int and float cases. Random and sorted
layouts share samples, and every case contains system missing, `.a` and `.z`.
They measure warm public grouping calls, not readers or arbitrary grouping
workloads. See the [protocol](README.md), [720 raw observations](results-2026-10-02/timings/raw.csv),
[60 representation summaries](results-2026-10-02/timings/summary.csv) and
[20 case ratios](results-2026-10-02/validation/ratio-summary.csv).

## What changed

The previous sorter decoded, validated and queried the R class of numeric
values during admission, sort comparisons and group-boundary detection. A
10,000-row development diagnostic counted 249,092 scalar reads. Preparing
private order keys reduces that to 10,000 prepared values with no scalar
reads during sorting. The count diagnostic is historical development evidence;
the final benchmark also verifies preparation counters on its clean candidate.

Known numeric columns now use captured, rooted readers and a bounded decode
tile. Validation still proceeds in row/key order. Each validated value becomes
an ordered 64-bit key: finite IEEE values retain their numeric order, both zero
signs share one key, and the highest 27 keys represent `.` through `.z`.
Sorting compares integers directly, without reconstructing R missing values or
rechecking classes at every comparison. Temporal inputs retain their existing
decoded-value semantics.

This was primarily a repeated-work problem. In the baseline, compact columns
were only 1.013–1.053× typed-double CPU, while both trailed ordinary vectors:
compact/ordinary ratios were 4.64–5.54×. The change removes repeated typed
validation and class handling as well as repeated compact decoding; the
benchmark does not separately attribute gains to each component.

The complete scalar path remains for calls containing strings, foreign ALTREP
providers or foreign class vectors, preserving callback order and mutation
visibility. Materialized compact ALTREP also takes that conservative fallback.
The measured sources use contiguous constructor storage. Retained chunks,
legacy formats, temporal inputs, all missing ranks, NaNs, signed zero and
callback/collection behavior have separate correctness coverage.

As a pairing check, medians of within-round compact/control ratios span
0.972–1.000× for typed doubles and 0.973–1.005× for ordinary doubles.
There is no claim that small differences within these ranges are repeatable
advantages. The retained CPU intervals were 139 ms–1.357 s; wall intervals
were 139 ms–1.358 s. Calibration targeted 150 ms, with slower operations
retaining a whole call.

## Memory cost

The key cache costs exactly `8 * rows * keys` bytes, in addition to existing
row-index arrays and outputs. Bounded decoding does not bound this complete
cache. The separate untimed R vector-heap diagnostic shows:

| Input | Baseline extra Vcell high water | Candidate extra Vcell high water | Key-cache payload |
|---|---:|---:|---:|
| 100,000 rows, one key | 2.40–2.44 MB | 3.30–3.34 MB | 0.80 MB |
| 100,000 rows, four keys | 2.80 MB | 6.10 MB | 3.20 MB |
| 1,000,000 rows, one key | 24.04 MB | 32.14 MB | 8.00 MB |

MB means 1,000,000 bytes. These are increases in R's vector-heap high-water
mark above the pre-call live heap, not process RSS or total allocated bytes.
They include keys, decode buffers, sorting scratch and results, and exclude
node and external-allocator memory.

Empty input now allocates no decode tile, and short input caps the tile to its
available rows. An untimed allocation profile on zero, one and three rows
confirmed removal of the two large buffers: the single-key profile records
184 bytes instead of 98,600. That is a count of sized allocation records,
not a claim that every allocator action was observed. Six short/wide checks
also cover 8,193 keys.

Narrower prepared keys could reduce this cost later. Non-temporal integer and
float encodings would need exact ordering and missing-code proofs; temporal
conversion can collapse distinct raw values and must retain decoded ordering.
No narrower-key performance or memory result is claimed here.

## Qualification and source identity

The clean baseline is `fd72c3448412b477dfb11e0cf4d26425d5c7a428`; the clean
measured package is `743c90000d4313a8f43c2c10ab4234deac4acf5c`.
Controller commit `ba14a5a6c08781e505c66d933ef70030fdc96f01` performs six
balanced rounds, alternates build order in fresh R processes, and checks all
six representation permutations. The [completion receipt](results-2026-10-02/timings/completion.json)
records 720 qualified observations and unchanged provenance. Complete result
bytes, metadata, source values and compact state agree across builds/rounds;
an independent integer-rank oracle also checks stable first-row indices.
An [independent artifact audit](results-2026-10-02/timings/independent-audit.json)
recomputed every median, speedup and paired representation ratio and verified
the complete matrix, semantic hashes, counters and source bindings.

The controller recorded the build R runtime hashes and `R --version`, but did
not snapshot the `Rscript` launcher or the runtime it executed around the
measurements. A [post-run runtime check](review-runtime-2026-10-02.json) queried
`R.home()` through the exact current `Rscript` launcher and found an R binary
matching both build receipts. This supplementary check identifies the current
runtime; it does not establish historical execution-binary identity. The
original timing receipts remain unchanged.

The final clean candidate passed 1,547 focused assertions, all 60 untimed
benchmark cases, and six empty/short/wide cases. Earlier runtime commit
`21557526` passed the full 51,682-assertion suite with no failures, errors or
skips and seven existing warnings. The final runtime adds only the documented
scratch-size fix and comment clarification; that exact delta is retained with
the [validation binding](results-2026-10-02/validation/validation-binding.json).
The full-suite development installation reused an unchanged Rust archive;
it is not represented as the final clean installation. Protocol tests separately
reject incomplete matrices, wrong preparation counters, unbalanced order and
inexact integer fields.

An initial run stopped after its first 60-row baseline CSV because the
controller rejected R's scientific notation for an exact byte count. It has no
accepted timing result. The corrected controller uses exact decimal parsing,
and this report uses a fresh complete run.

Main's independent Arrow collection-policy change, `895dd204`, subsequently
merged without conflict as `60b9b0c1`. The grouping implementation is unchanged
by that integration. A clean integration build passed 6,070 assertions in the
focused grouping and owned-buffer suites with no failures, errors, skips or
warnings. Its [source and validation binding](results-2026-10-02/validation/integration-binding.json)
is separate from the measured source binding; these timings are not relabelled
as measurements of the merged package.
