7.79 times on independently randomized half-missing inputs. It also improves
missing-free inputs by 1.24 to 1.30 times. This removes the large dense-missing
penalty left by the preceding native comparison change. Compact float
comparisons are unchanged and remain faster on these inputs.

## Why the loop changes

The preceding decoded-double loop branched on NaN at every row. The new exact
loop computes IEEE comparison and missing-order comparison, then selects the
answer with masks. A local unsigned key gives observed values rank zero,
system missing rank one and letter tags their byte plus one. The tag byte is
widened before addition because an observed double can contain byte 255 there.
Canonical payload validation accumulates without short-circuiting. Unsupported
NaNs still decline the complete native call and use the existing fallback.

Computing that exact classification everywhere was itself too expensive on
ordinary inputs. The final loop first proves a 64-row block ordinary by reducing
the maximum absolute IEEE bit pattern. A maximum no greater than infinity
excludes all NaNs, while preserving observed infinities and signed zeros. Such
blocks use direct vector comparisons. Other blocks use the exact masked loop.

Four consecutive failed proofs select at most 16,384 additional exact rows,
then proof attempts resume. This bounds optional proof work on dense inputs
without letting a short dense prefix select full decoding for an arbitrarily
long ordinary tail. Every row still receives the required validation. The
policy creates no cached column-domain fact and changes no ownership rules.
Operator and storage dispatch stay outside the row loop. Scalars and retained
compact-float kernels are unchanged.

The recorded arm64 assembly uses vector unsigned comparisons/selects for the
maximum reduction and SIMD comparison loops. Compiler evidence supports the
mechanism; it does not establish a separate speed claim or performance on
other architectures. A raw Stata missing threshold cannot simply replace the
canonical R NaN checks here because these operands are already decoded doubles.

## Rejected stages and the regression test

The unconditional masked kernel `764c6f51` improved random dense inputs by
7.37 to 7.79 times but used 1.83 to 2.17 times as much CPU on ordinary/sparse
doubles. It was rejected. Its [dense](results-2026-10-03/density-timings-v1/summary.csv)
and [ordinary/sparse](results-2026-10-03/ordinary-timings-v1/summary.csv) observations
and independent audits are preserved.

The first adaptive kernel `76b46d92` recovered ordinary throughput, but its
four-failure rule selected the exact loop for the rest of the entire span.
The real caller passes a million-row contiguous double span. A regression test
counting work in the actual pair kernel showed that a 256-row missing prefix
caused all 1,000,000 rows to run through the exact loop. The
[recorded failing test](results-2026-10-03/validation/bounded-prefix-red.log)
passed after the bounded-window change. The test checks that fewer than 10%
of rows take the exact path, without a noisy timing threshold. The
[first adaptive dense](results-2026-10-03/adaptive-density-timings-v1/summary.csv)
and [ordinary/sparse](results-2026-10-03/adaptive-ordinary-timings-v1/summary.csv)
results remain separate historical experiments.

## Measurement contract

Each input has one million rows. Six balanced rounds alternate build order
and representation order in fresh R processes. The density and pattern panels
cover all six permutations of their three layouts. The ordinary/sparse panel
uses the existing native-comparison controller and all six representation
orders. Typed doubles implement the same Stata missing ordering as compact
floats. Bare R comparisons with missing values propagate NA, so they are not
an equivalent-work missing-bearing reference.

Random-half operands use independent missing positions. Prefix, suffix,
clustered and alternating patterns put missing values at the same positions
in both inputs. The alternating pattern has 500,032 missing rows because the
million-row input contains an odd number of 64-row blocks. Different patterns
do not isolate branch prediction. Compact controls retain unequal 8,191 and
16,385-value chunks; decoded doubles are contiguous.

All panels check full input/result hashes, metadata, native eligibility and
before/after representation states outside timing. Dense and pattern panels
also record independent rank hashes and exact missing counts. Native
eligibility is not a per-call timed entry counter. Result allocation and
automatic collection are included. Construction, explicit collection,
calibration and verification are excluded. Actual retained CPU intervals range
from 205 to 338 ms. Local builds, tests and other benchmarks were stopped during
measurement. This is one arm64 macOS host with R 4.6.1 and normal desktop
activity, not hardware isolation. Results describe warm operations, not reader
throughput, arbitrary layouts or confidence intervals.

Before/after provenance binds the exact runtime, controller files, clean source
inventories, compiler and installed library. Independent audit programs
recompute every result summary and verify complete worker/raw identity and
qualification bindings. The audit scripts preserve their original local paths;
the published receipts and raw files are the portable evidence.
