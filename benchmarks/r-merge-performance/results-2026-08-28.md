# R merge performance - 2026-08-28

## Result

In these default workflows, `dta_merge()` had a similar median to dplyr on
ordinary R columns and was faster on columns read from DTA files. dplyr and
base R materialized intermediate values or reconstructed classed outputs.
Their wider outputs also increased cumulative allocation. Both tools left the
compact source columns untouched.

| Method | Input columns | 1:m median | m:1 median | 1:m allocated | m:1 allocated |
| --- | --- | ---: | ---: | ---: | ---: |
| `dta_merge()` | Stata classes | 0.101 s | 0.097 s | 0.61 GB | 0.62 GB |
| dplyr `full_join()` | Stata classes | 1.716 s | 1.411 s | 9.27 GB | 9.43 GB |
| base `merge()` | Stata classes | 5.125 s | 7.433 s | 23.26 GB | 31.23 GB |
| `dta_merge()` | Standard R | 0.107 s | 0.108 s | 0.66 GB | 0.79 GB |
| dplyr `full_join()` | Standard R | 0.115 s | 0.108 s | 0.74 GB | 0.76 GB |
| base `merge()` | Standard R | 1.576 s | 1.855 s | 2.06 GB | 2.06 GB |
| Stata 18 MP `merge` | Native DTA | 0.257 s | 0.329 s | Not measured | Not measured |

The `dta_merge()` result has 201 columns because it coalesces 60 shared
variables and creates `_merge`. Stata produces the same shape. dplyr and base R
retain suffixed copies of the 60 shared variables and produce 260 columns.
Base R and Stata sort by the key, while `dta_merge()` and dplyr retain input
order. The table therefore compares each tool's default full-merge workflow,
not identical output construction.

## Method

- Host: Apple M4 Max, macOS Tahoe 26.5.2, arm64
- R: 4.6.1, `aarch64-apple-darwin25.4.0`
- dtatools: 0.6.0, clean revision
  `8e0b580f4fcf130a79eea82cb72e24390c5ad395`
- dplyr: 1.2.1
- vctrs: 0.7.3
- Stata: 18 MP, 8 cores
- Fixture: deterministic 200,000 by 151 master and 360,044 by 110 using
  dataset, joined on a character `caseid`, with 60 shared non-key variables
- Result: 440,044 rows; 201 columns for `dta_merge()` and Stata, 260 for dplyr
  and base R
- Stata-class output: 61 compact byte or int columns and 138 Stata double (`dta_double()`)
  columns before `_merge`
- Standard-R control: one ordinary character key plus base integer and double
  columns containing the same values
- R statistic: nine-iteration `bench::mark()` medians for `dta_merge()` and
  dplyr; five-iteration medians for base R
- R memory: cumulative allocation from `bench::mark()`, not peak RSS
- Stata statistic: median of seven timers; each timer includes reading the
  using file and excludes reading the master
- Cache state: warm operating-system cache
- Correctness: every timed expression ran once before measurement; checks
  covered row and column counts, key multiplicities, merge-indicator counts,
  and a shared variable against the source fixture. Each Stata iteration
  checked row-key uniqueness and merge-indicator counts after its timer.

Exact R command:

```sh
DTATOOLS_BENCH_LIB=/tmp/dtatools-exact-bench.HO7Mom/lib \
  Rscript --vanilla benchmarks/r-merge-performance/run.R 9 5
```
