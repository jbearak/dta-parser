# Stata oracle for five survey corpora, October 1, 2026

All 1,879 readable files passed both live-Stata round-trip comparisons, with
zero mismatches. The inventory contained 1,881 regular DTA files; the two
known malformed MICS files remained excluded under the unchanged rules that
bind each exclusion to its ID, byte length and SHA-256. No Haven reader or
Haven conformance test ran.

The tested package was built from
`61954ee88431eb2212e36a24ca8db1781e932ac7`. This is the preserved v3 package,
not the later integration build. Integration commit
`a4cbc8707083df95134f303aadcba01a259f7bc3` subsequently added the main branch's
summarize functions without changing the reader, writer or Arrow
implementation. Its separate
[integration checks](../r-file-readers/results-2026-10-01/integration-validation.json)
do not replace or relabel this oracle run.

These files total 57,114,293,618 bytes. File and directory symlinks were
excluded; the two MICS directory aliases therefore did not duplicate files.
The canonical gate covered its exact 1,823-file DHS/MICS/NSFG inventory and
required 1,821 passes plus two bound exclusions. The separate supplement
required all 58 ENADID/WFS files to pass, with no exclusions. It did not
weaken or replace the canonical gate. The supplement was rerun with only
ENADID and WFS selected; its published artifacts come from that fresh
58-file run. The canonical evidence remains unchanged. Both gates completed
their full survey inventories; neither used a historical archive or a
recovered tail.

For each successful source, the unchanged
[worker](verify-worker.R) performed two workflows:

1. `read_dta()` → `save_dta()` → live Stata comparison with the source.
2. `read_dta()` → `save_arrow()` → `read_arrow()` → `save_dta()` → live
   Stata comparison with the source.

The exported writer names are `save_dta()` and `save_arrow()`. This produced
3,758 successful source/output comparisons. The worker used the public
default container, dibble; Arrow restored the saved container. This oracle
did not independently rerun the whole corpus as tibbles or exercise projected
reads. Source releases present were 105, 108, 110, 111, 113, 114, 115, 117 and
118. The 58 supplementary files were all release 118; a synthetic release-119
wide case was not part of these two corpus gates.

The unchanged [Stata comparator](stata-compare.do) checked dimensions,
ordered column names, storage types, display formats, dataset and variable
labels, value-label assignments and definitions, dataset notes, and every
stored value. Its established rules normalize legacy Windows-1252 and modern
UTF-8 text and allow corresponding string-width changes. These are semantic
comparisons, not byte-for-byte file comparisons. Arbitrary characteristics,
including variable notes, remain outside this comparator's coverage even
though the current read model preserves them.

The separate [comparator controls](test-stata-comparator.R) also passed.
Seven positive checks covered source self-comparisons for releases 115, 117
and 118, empty files, the `__1` variable-name guard, and a 10,000-row,
1,000-column fixture. All ten deliberately introduced mismatch categories
were detected: dimensions, variable names, storage type, display format,
dataset label, variable label, value-label assignment, value-label
definitions, dataset notes and stored values. The wide control took 0.78
seconds against its unchanged 2.5-second test bound. These controls are
separate from the corpus pass counts; this report is a conformance result,
not a performance benchmark.

The runs used R 4.6.1 and Stata/MP 18.0.119. A Stata preflight passed before
the corpus run. The corpus scheduler admitted at most 16 workers under its
96 GiB estimated-memory limit, and each Stata comparison used one processor.
Canonical, supplementary and control runs executed sequentially. The
[supplemental protocol](verify-extra-cache.md) gives the reproducible
commands. Its [published patch](results-2026-10-01/supplement/adapter.patch)
changes only corpus selection and the exact supplemental gate assertions;
the worker and comparator stayed byte-identical to the canonical versions.

The [source audit](results-2026-10-01/build/source-commit-audit.json) matched
all 409 package files to the tested commit. The
[build record](results-2026-10-01/build/build-bindings.json) binds that source
to the installed package used here. Both corpus runs rehashed their complete
input bytes afterward and confirmed unchanged inventories, installed package,
oracle sources and executable bindings. The canonical runtime recheck also
matched its initial R, Rscript, Stata and dependency hashes; native R matched
the v3 build receipt. The control run's before/after bindings matched too.
The shared binder fingerprints the installed Haven package as incidental
provenance; it invokes no Haven reader or test.
