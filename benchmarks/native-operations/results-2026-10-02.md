# Native numeric operations, 2026-10-02

The new kernels reduce CPU across the measured compact-column operations while preserving result values, output storage, and unmaterialized inputs. Six fresh-process rounds compare main after PR #283 with commit `758a8275909513c5ac15a9dbb75e519c5134b230`. The run contains 2,976 qualified observations across million-row DTA and Arrow inputs, four storage widths, and ordinary-double controls.

Matching improves 72.3–87.0× and membership 68.3–87.4×. Mean improves 10.0–18.0×, range 14.3–19.0×, and totals 9.8–12.8×. Arithmetic improves 18.4–33.8× but does **not** reach ordinary-double parity. `summ()` and early-exit `anyNA()` also remain slower than their ordinary-double controls. The table below reports these gaps.

## Arithmetic controls and remaining cost

`dta_double` applies Stata missing/result rules and constructs a typed result. Bare-double arithmetic returns an ordinary R vector. Compact arithmetic can additionally select a wider output type and recompute into that representation; the typed-double control always has a double destination. These controls make the extra work visible rather than treating their contracts as identical.

| Operation | Compact (ms) | Typed double (ms) | Bare double (ms) | Compact / typed CPU |
| --- | ---: | ---: | ---: | ---: |
| `x * 2` | 1.212–1.853 | 0.267–0.297 | 0.248–0.278 | 4.24–6.66× |
| `x / 2` | 1.319–1.977 | 0.298–0.328 | 0.242–0.270 | 4.32–6.05× |
| `x + x` | 1.626–2.239 | 0.270–0.305 | 0.266–0.283 | 5.88–7.59× |

Compact arithmetic remains 4.2–7.6× the typed-double CPU and 4.9–8.0× the bare-double CPU in this run. Direct typed spans remove repeated scalar decoding, but storage-fit checks and promotion still add work; some of those loops remain scalar. This change is a substantial improvement, not evidence that all compact operations match doubles.

## What changed

A shared typed block reader chooses storage width, encoding version and temporal conversion before scanning a block. Tagged predicates and missing-code extraction use it; `anyNA()` answers directly from exact counts on known unmaterialized storage. Materialized and foreign inputs retain their existing paths.

`egen` reductions and row operations read bounded blocks while preserving ordered accumulation, validation order and Stata missing rules. Mean uses R's ordered extended-precision algorithm, range combines extrema in one scan, and `summ()` fuses masks and weighted moment calculations. The mean/range admission guards retain custom methods, tracing and lazy argument behavior. The R-derived mean implementation is credited in the package notice.

Matching replaces formatted hexadecimal strings with normalized binary keys and a native hash table. Zero signs normalize, system and tagged missing identities remain distinct, and first-match and set ordering are preserved. This removes formatting, string allocation and several full-column traversals.

Arithmetic chooses operator, source width, scalar direction and destination before its inner loops. Same-width compact inputs, including missing-bearing inputs, are read directly from contiguous spans. Retained inputs split at either chunk boundary. Missing detection, result validation and storage selection happen in the producer; promotion writes a fresh wider result. Unsupported classes, shapes and dependency changes use the existing fallback.

Compiler diagnostics at the accepted source's `-O2` setting report 16 vectorized ordinary-double loop variants, 384 observed compact variants and 160 missing compact variants. Some storage-fit variants remain scalar. No fast-math options or reassociated reductions were introduced.

## Protocol and limits

Each round starts a fresh R process per build. Build order alternates. Cases retain a fixed order; two-representation order alternates, and arithmetic rotates and reverses its three representations across six rounds. Calibration runs outside the retained interval for at least 20 ms, then chooses fixed repetitions targeting 150 ms. Explicit GC, input reads, qualification and hashing are outside timing. Public dispatch, output allocation and automatic GC are included. Retained intervals span 0.058–3.172 seconds; 0 are shorter than 20 ms and 11 are shorter than 100 ms. The ratios compare medians and have no formal uncertainty interval.

The worker checks complete result bytes and output storage against ordinary references, using independent base operations where semantics agree. Full `summ()` objects must also match between builds. It verifies source value hashes before and after each width/format operation sequence and compact state around each retained interval. Every timed candidate arithmetic call must increment the native producer counter. The controller checks all 248 unique cases in every process and verifies source/build receipts before and after timing.

The timing commit precedes a fix for `range()` calls with `NULL` operands, which these cases do not contain. Source attribution and runner argument validation were also clarified afterward. The archived controllers and build records retain the measured versions.

This is one warm-data host comparison using R 4.6.1 and Apple clang 21.0.0 on arm64 macOS. Builds and tests did not overlap timing; unrelated desktop activity was not hardware-isolated. File fixtures have system missing values, matching uses self-lookup, and summaries are unweighted with default options. The measurements do not establish performance for tag-rich data, nonmatching tables, detailed summaries, row maxima, small inputs or arbitrary decorated/foreign vectors. They do not measure read-plus-consume latency or claim a new parser improvement.
