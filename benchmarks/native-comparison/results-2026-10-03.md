# Native comparison follow-up, 2026-10-03

Decoded-double pair comparisons improve by 4.06–5.82× CPU in the first
experiment. Subsequent changes bring retained float pairs to 1.01–1.10× the
CPU of those improved typed doubles in the missing-free and sparse-missing
matrix. This is a narrower result than parity for every operation or data
distribution. Dense-missing performance qualification is still pending.

Three separate experiments each contain 432 observations. Their speedups
compare corresponding medians within each experiment; they must not be
multiplied into an end-to-end speedup. All use public operators on one million
rows, including logical-result allocation and automatic garbage collection.

| Experiment | Before | After | Measured result |
| --- | --- | --- | --- |
| Double-pair kernel and retained scheduling | `c17ef21e` | `6f95ab2c` | Typed-double pairs use 4.06–5.82× less CPU; missing-free typed pairs use 0.52–0.55× bare-double CPU |
| Direct IEEE float comparison with exact missing-rank correction | `6f95ab2c` | `e36e50c2` | Float pairs improve 1.35–1.42× CPU, reaching 1.07–1.24× typed-double CPU |
| Below-missing-threshold fast path | `e36e50c2` | `c21a79b3` | Float pairs improve another 1.08–1.21× CPU, reaching 1.01–1.10× typed-double CPU |

The final threshold experiment takes 0.392–0.421 ms CPU per float-pair
comparison. On missing-free inputs that is 0.55–0.58× bare-double CPU.
Scalar comparisons are unchanged controls, with before/after CPU ratios within
0.5% in this last experiment. Bare R comparisons with missing values propagate
NA; their contract differs from Stata's ordering and their ratios are not
used as equivalent-work claims.

## Why the kernels are cheaper

The previous decoded-double pair loop reconstructed a value-and-missing-rank
record for both operands at each row. The new loop compares ordinary doubles
directly. Only NaN operands need their payloads checked for supported missing
codes. The operator is selected before entering the loop. Unrecognized NaNs
decline the native fast path and retain the existing fallback behavior.

Float pairs previously constructed ordered integer keys for every row. Direct
IEEE comparison already handles ordinary values, signed zero and infinities.
The kernel corrects that result when an operand is a Stata missing code.
It dispatches storage, operator and Stata release outside the row loop.

The threshold experiment avoids even that rank decoding when both operands
are less than the first reserved missing encoding. Ordered comparisons also
exclude NaNs from this path. Values at or above the threshold retain exact
classification: modern imports recognize precisely 27 codes and can contain
observed values between them, high finite values or positive infinity. Legacy
releases retain their existing broader classification. This shortcut uses
the current values and requires no cached column-domain claim.

Generated code is evidence about the implementation, not a performance result:
the direct version vectorizes, whereas the threshold branch is scalar on this
arm64 build. Nevertheless, the latter wins all 48 paired-round float-pair
comparisons in the measured missing-free/sparse matrix. Its exceptional path
needs a separate dense-missing regression check before unconditional adoption.

Scalar float comparisons retain exact widening to binary64; the R scalar is
never rounded to float. Temporal and mixed-storage cases retain their existing
routes. No reader encoding, public result type or missing-value order changes.

## Scheduling trades CPU for elapsed time

Retained float regions now use the same serial policy as plain compact floats
and existing scalar fast paths. The region walker still handles differing
chunk boundaries; it no longer starts workers for this small kernel. This
policy also applies when a positive thread count is requested.

The first experiment isolates that scheduling change before either float-pair
loop improvement. With automatic threading, retained float CPU improves
1.28–1.45×, while elapsed time becomes 2.05–2.64× longer. Single-thread results
remain approximately unchanged. Thus this change reduces computation but is
not an elapsed-time improvement. The later loop experiments reduce both CPU
and elapsed time relative to that serial version. No combined end-to-end
elapsed-time claim is made from separate runs.

## Protocol

Each experiment has six balanced rounds, fresh R processes for each build and
round, and all six compact/typed-double/bare-double representation orders.
The 36 cases per build cover `<` and `==` pairs, scalar `< 1.01`, thread settings
1 and automatic, and zero or sparse occurrences of all 27 missing codes.
Retained X spans contain 8,191 values and Y spans 16,385 values. This exercises
different boundaries while keeping values exact across representations.

Full logical results, decoded input bytes, metadata, native eligibility and
compact/materialized state are checked outside timing. Construction, explicit
collection, calibration and verification are excluded. Calibration targets
300 ms CPU intervals; the threshold experiment retains 232–330 ms intervals.
All local builds, tests and other benchmarks are stopped during measurement.
The host is arm64 macOS with R 4.6.1, without hardware isolation from ordinary
desktop activity. These are warm-operation measurements, with no reader
throughput, memory-use or confidence-interval claim.

Each controller verifies the complete recorded package inventory, installed
library, actual Rscript/runtime and controller files before and after timing.
The first baseline's package inventory matches merged main `460db463`.
The later integration commit `94e70987` has exactly the same tree as measured
runtime `c21a79b3`; it reconciles the squash-merge history without changing code.
