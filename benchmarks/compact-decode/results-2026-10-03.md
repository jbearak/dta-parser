# Compact double decoding, October 3, 2026

Specializing the compact decoder improves CPU time for first materialization
by 2.030 to 4.771 times across all 24 measured cases. The change moves interrupt
polling and storage, missing-policy, and temporal dispatch outside bounded
inner loops. It preserves the allocation and ownership contract established
by the earlier compact-materialization change.

This is the cost of producing a newly allocated ordinary double vector from
compact storage. It includes output allocation and automatic GC. It does not
measure Arrow ingestion, a repeated access to an already materialized vector,
or parity with an ordinary-double no-op.

The batches range from 2 to 72 ms CPU and 2 to 71 ms elapsed, with no zero-duration
intervals. Aggregate CPU intervals range from 150 to 208 ms. Each batch forces

those intervals by 32 does not improve the underlying timer resolution.
There are no uncertainty intervals or cross-host claims.

The baseline materializes 19,200 outputs and the candidate 58,592 before
reaching their per-case interval targets. Every output is checked bit for bit.
Both builds record exactly zero compact-copy and compatibility-copy bytes.
Their separate single-call allocation profiles each record 8,000,048 bytes,
including the 8 MB double output. Vcells live/high-water observations are
reported separately and overlap those allocation measurements; they are not
process RSS.

Automatic GC remains inside timing. It accounts for about 17.4% of pooled
baseline CPU and 42.9% of pooled candidate CPU. The candidate completes more
allocating operations per interval, so these pooled percentages do not isolate
a GC optimization. The result measures the complete allocating consumer;
it does not attribute every saved cycle to decoding alone.

## Why it improves

The old plain-span loop retains an interrupt branch and runtime owner/temporal
work at each element. In the measured baseline's no-missing path, generated
code computes temporal arithmetic even for ordinary numbers. Missing-bearing
paths call a scalar decoder for each value.

The new decoder chooses a typed kernel once per contiguous span using the
storage width, temporal policy, format family and existing missing-count proof.
It checks interrupts between tiles of at most 16,384 elements. A typed tile
contains only loads, decoding and stores. `memcpy` loads preserve support for
unaligned raw and retained spans. On the measured arm64 build, the compiler
vectorizes no-missing integer and float widening. Missing-bearing kernels keep
the existing exact classifiers but inline their work. The
[baseline excerpt](results-2026-10-03/validation/assembly-baseline-excerpt.s),
[candidate excerpt](results-2026-10-03/validation/assembly-candidate-excerpt.s),
and [installed-library binding](results-2026-10-03/validation/assembly-binding.json)
record these observations from the exact measured installed libraries.

The code keeps modern and legacy missing encodings distinct. Modern float
storage can contain high finite values, infinities, and gaps between Stata
missing codes. A blanket numerical threshold would change their meaning.
Generic NaNs also make the cached missing count nonzero. Regression fixtures
therefore keep finite/Inf/gap-only values separate from NaNs and explicitly
check the real cache that selects the no-missing branch. No invalid descriptor
is manufactured to reach that branch.

The existing materializer's rooted read claim, callback retry and unwind
cleanup remain unchanged. This change improves its decoder rather than
relaxing alias or reentrant-mutation behavior.

## Protocol and source binding

The 24 cases cross byte, int, long and float storage; constructed or retained
backing; and zero, 62 sparse or 843,750 dense missing values. Sparse and dense
cases include all 27 Stata missing ranks. Retained input uses an immutable
8,191-row chunk adapter, not an Arrow read. All inputs are ordinary numeric
values for throughput; separate correctness tests cover dates and datetimes.

Every request gets a fresh metadata handle sharing one rooted compact source.
Its standard external `DATAPTR_RO` consumer allocates and fills a distinct
double output. The source stays compact and bitwise unchanged. A mutation of
a decoded warm-up output verifies alias independence. This screen covers
aliased inputs only; it does not establish private-input or tiny-vector gains.

There is a fresh R process for each build and round. Paired build order and
backing order alternate. Six rounds cover all six missing-density permutations.
Input construction, metadata-handle setup, explicit GC, value checks and
memory profiling are outside timing. Output allocation, decoding and automatic
GC remain inside. Every target and source is fully checked, and the unchanged
external probe binary is shared by both builds. The
[protocol](results-2026-10-03/timings/protocol.json),
[completion](results-2026-10-03/timings/completion.json), and
[independent audit](results-2026-10-03/validation/independent-audit.json)
record the retained contract and the full artifact checks.

The measured baseline is clean `bd78a06e`, which already contains the redundant
compact-copy removal. The measured candidate is clean `83746313`. Their receipt
variant labels are respectively `candidate` and `baseline` because those labels
belong to the clean-build tool; the diagnostic comparison labels are separate.
Both package/runtime receipts, the probe source/binary receipt and controller
hashes agree before and after timing. The recorded
[source delta](results-2026-10-03/timings/source.patch) isolates the package changes.

Final qualification uses clean `0da838e0`, which adds the branch-admission
regressions. Its decoder production files are byte-identical to the measured
candidate. The subsequent parent-PR evidence merge changes no package files.
The [qualification binding](results-2026-10-03/validation/source-binding.json)
keeps these distinct source states explicit.

[conformance log](results-2026-10-03/validation/conformance-v2.log), and
