# R I/O optimization, 2026-10-01

These measurements compare optimization candidates with PR #275, not with
v0.10.0. The retained baseline has the production sources recorded at
`78050a30`; merge commit `e0ed3986` has identical production sources. The
public R writer names are `save_dta()` and `save_arrow()`.

## Final combined result

The combined library retains the reader changes, owned Arrow string capture,
the narrower integer DTA writer, and namespace setup changes. The mixed-batch
DTA writer described below was rejected. These are paired changes against
PR #275, not against the last release:

| Public operation and case | Call wall | Call CPU | Process peak RSS |
| --- | ---: | ---: | ---: |
| `read_dta()`, primary 1 GB, automatic threads | -3.3% | -1.5% | -0.8% |
| `read_arrow()`, wide input, automatic threads | -6.5% | -10.9% | -0.02% |
| `read_arrow()`, wide input, one thread | -18.3% | -18.4% | +0.07% |
| `save_dta()`, ordinary 1 GB | -7.9% | -8.1% | -0.09% |
| `save_dta()`, ordinary 100 MB | -7.6% | -7.5% | -0.4% |
| `save_arrow()`, ordinary 1 GB | -26.0% | -42.5% | -41.9% |
| `save_arrow()`, ordinary 100 MB | -19.9% | -38.1% | -27.2% |
| Namespace setup | -3.6% | -3.6% | -4.6% |

The main combined matrix contains ten pairs per reader case, eight per writer
case and twenty namespace-load pairs. The 1 GB ordinary Arrow write's median
wall time fell from 0.7215 to 0.520 seconds; peak RSS fell from 2.81 to 1.63 GB.
Its paired wall ratio was 0.7396, with a 95% bootstrap interval of 0.6728 to
0.7551. The ordinary DTA writer's paired wall ratio was 0.9214, with an
interval of 0.9188 to 0.9579. These gains do not extend to every input:
package-owned writer controls and narrower Arrow reads remain near parity.

Two reader cases received longer checks:

- The twenty-pair single-thread wide-DTA recheck had wall and CPU ratios of
  0.9929, with both 95% intervals below 1.0. Peak RSS increased by 0.13%,
  about 6 MB on a 5.24 GB process. This did not reproduce the possible CPU
  regression in the initial isolated screen.
- Primary 1 GB Arrow with automatic threads used 3.2% more call CPU in the
  ten-pair combined matrix (95% interval +1.6% to +5.4%), with unchanged
  median wall time. The twenty-pair recheck had a CPU ratio of 1.0017
  (interval 0.9661 to 1.0227), wall ratio 0.9911 and RSS ratio 0.9954.
  The increase was not reproduced. Both runs are retained; there is no
  claimed improvement or guarantee of zero CPU cost for this case.

The Arrow reader change has no clear effect on the narrower primary files.
The DTA reader change has no clear effect on the wide input with automatic
threads. Its ten-pair single-thread wide-input interval is broad enough to
include an 8.1% CPU increase, which prompted the longer combined recheck above.
Arrow writer improvements apply to ordinary R character inputs. The
package-owned writer controls and the unchanged DTA writer remain near
parity in that screen.

The namespace change avoids constructing two unused full dependency
profiles. It still validates the same installed artifacts and retains live
per-operation checks. The median namespace timer fell from 195.5 to 188.5
milliseconds. This does not restore v0.10.0 startup performance.

## Rejected mixed-batch DTA writer

A candidate that split ordinary fixed strings from direct numeric encoding
passed its correctness checks but did not improve the clean writer workload.
On the ordinary 1 GB fixture, the paired wall ratio was 1.0015, with a 95%
interval of 0.9964 to 1.0088. The CPU ratio was 1.0013 and peak RSS was
unchanged. The [complete screen](results-2026-10-01/dta-mixed-writer-screen/writes-summary.csv)
is retained, including all controls and successful output qualification.

The batch requires every numeric column to have direct backing. A separate
1,000-row fixture diagnostic found that its lazy `id` sequence had no direct
backing both before and after writer preparation. After `datasig()`, all
numeric columns had direct backing. The earlier diagnostic profiler called
`datasig()` before saving, so its profile did not establish admission for the
clean first-save measurement.
The candidate is not part of the retained implementation. Foreign numeric
callbacks remain ordered as before; admitting them and moving direct reads
after those callbacks would not preserve observable behavior.

## Measurement boundaries and correctness

The [protocol](README.md) describes paired order, process isolation, warm
filesystem caches, timers and qualification. All timing windows exclude
builds, tests, profiles and other benchmarks. Arrow verification is enabled.
Call CPU includes all worker-thread CPU. Peak RSS is for the whole process,
including namespace loading and input preparation, not an allocation count
for the save or read call alone.

Each full single-format reader screen checks twelve complete dataset
signatures before timing. The combined matrix checks twenty-four, covering
every fixture, format, thread setting and library; each targeted recheck
checks two. The full writer screens, including the final combined matrix,
pass 32 first/final output-signature workers and 16 separate input
preservation workers. Warning sequences match throughout the writer runs.
No timed writer call is preceded by a warm-up write or dataset signature.

The wide private fixture has 724,115 rows and 5,972 columns. Primary fixtures
have 231,956 or 2,320,123 rows and 40 columns. Ordinary writer fixtures have
222,711 or 2,227,111 rows and 40 columns. Public provenance records retain
input hashes and dimensions without input paths. Published writer and
namespace raw records omit only private command and output-path fields;
`publication.json` records hashes of both forms. All other raw fields remain.

The [build records](build-bindings-2026-10-01/build-bindings.json) bind source
inventories, exact source patches, build-log hashes and installed files.
The startup screen is exploratory and lacks the reader/writer screens'
before-and-after run provenance. Its R-only source snapshot and reused native
DLL are separately recorded. Toolchain entries are recording-time
observations, not proof of historical compiler identity.
The final twenty-pair namespace run shares the combined writer run's
before-and-after library bindings. Its unchanged `load-worker.R` is recorded
at the final source commit with SHA256
`e1ccb1018447a32c38a7e6c8b4999fe57743b42033919dc50cf7e5f449d3929e`;
this worker hash was checked after the run, not captured by the writer
provenance script beforehand.

The host is an Apple M4 Max running arm64 macOS 26.7 with 16 logical CPUs,
R 4.6.1 revision 90187, and the same installed dependencies in both libraries.
These are local warm-cache results, not a claim about every machine or dataset.

## Validation

The final package source is commit `ec967fdd080d841bb71ff73dac3720dd05a38bba`.
Its frozen build contains all 409 tracked package files, each verified against
that commit. The final native library SHA256 is
`be54fade4dcfdbe40014cafb62d6ca7503ab22d00a96d27bb8fabc1638cdfc48`.
The [validation record](results-2026-10-01/validation.json) contains archive
and log hashes.

- R source archive validation passed. `R CMD check --no-manual` ran 27,341
  assertions with zero failures and skips, and seven known test warnings.
  Check reported zero errors, three warnings and two notes, matching the
  reviewed baseline. These concern the macOS link target, vendored files,
  and compiled-code checks. Tests used pinned labelled 2.16.0 and haven 2.5.5.
- Rust passed 33 bridge tests, 295 default core/integration tests, and 146
  core tests with the R-adapter feature. Format checks, Clippy with warnings
  denied, Rustdoc and offline package verification passed.
- Shared conformance passed 32,085 decoded-cell comparisons across 22
  immutable fixtures, ten deterministic native gates and the fixture oracle.
- The build recorder passed nine tests. All eight retained experiment patches
  replay to the recorded hashes. Rejected and superseded snapshots are labeled.

Regression coverage includes legacy missing-value layouts, both byte orders,
temporal values, sliced buffers and owner lifetimes, string-region boundaries,
UTF-8, warning counts, source preservation, interrupts and callback order.
LargeUtf8 offset arithmetic and the 2 GiB threshold are tested without
allocating a character array larger than 2 GiB in the new regression tests.
