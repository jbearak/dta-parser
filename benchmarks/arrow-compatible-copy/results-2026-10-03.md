# Copy compatible Arrow numeric chunks in bulk

The candidate replaces a per-value native loop with one bulk copy for each no-null Arrow chunk whose physical values already match the destination R vector. In this screen, read-return CPU speedups for the three affected routes were 1.051–1.341×. Read plus the first complete consumption improved 1.030–1.114×. The source still allocates an independent R vector; this is a copy optimization, not a zero-copy reader.

The independent artifact audit and separate integration qualification passed. The measured source is fixed below; the integration includes main `20ec12ce` and the decoder parent from [PR293](https://github.com/jbearak/dta-parser/pull/293). This screen does not establish universal reader parity.

## Results

These are medians of six fresh-process observations per build and case. The read-return and full-workflow columns come from separate workers. CPU includes automatic garbage collection.

The unchanged nullable Float64, nullable Int32 and Float32-widening controls had read-return CPU ratios of 0.989–1.023×. The retained compact Int16 control had equal read-return CPU medians for both builds at both thread settings. Its one-thread wall ratio was 0.923× over short intervals, despite equal CPU medians. Small control differences should not be attributed to the changed copy branch.

Requesting 16 threads used more total CPU than requesting one thread for these inputs. In particular, the profiled Float64 case saved CPU at 16 threads while its read wall median remained unchanged. This patch does not change thread planning or scheduling.

GC remained a substantial part of the measured read. The no-null Float64 read-return cases recorded median GC CPU of 27–29 ms, and the Int32 cases 16–16.5 ms. These observations do not isolate GC causes or justify subtracting GC from the public read contract.

## What changed

The old loops were already native Rust loops. They did not evaluate R expressions or call back into R for each value. Compiled arm64 output nevertheless retained per-value checks and scalar transfers, even after the iterator closures were inlined.

The new helper checks the concrete chunk type, skips empty chunks, and checks the chunk's null count once. For a no-null chunk, it copies the selected typed value slice into the existing independent R allocation. Compiled candidate output has a call to `memcpy` for each admitted chunk. Nullable chunks keep their previous per-value missing-value policy.

Only three output routes changed: `PayloadDouble` from Float64, `SemanticDouble` from Float64, and `Integer` from Int32. The generic Int32 scan for the R missing-value sentinel is still present. Float32 widening, temporal conversion, checked 64-bit conversion, retained compact ownership, checksum validation and scheduling are unchanged.

Bulk copying preserves every floating-point bit, including signed zero and missing payloads. Direct tests cover sliced all-valid and nullable bitmaps, empty and unequal chunks, wrong-type empty input, source independence, destination canaries, and an Int32 null slot containing a non-sentinel physical value. A wrong-type empty chunk still fails before the empty-chunk shortcut; a correctly typed empty chunk never performs pointer arithmetic or a copy.

## Measurement and source binding

The screen contains 336 observations: seven routes, two requested thread settings, two workflows, two builds and six rounds. Every file has 2,000,000 rows and eight columns. Fixture creation inspected and recorded the actual physical schema and all 31 uncompressed record batches, with 30 batches of 65,536 rows and a final batch of 33,920 rows. Each nullable control has at least one null in every selected batch. Retained compact ownership and its 31 chunks per column are checked separately from compact ALTREP state.

The full consumer computes `sum(as.double(x), na.rm = TRUE)` and the complete `is.na(x)` vector for every column. Complete value bytes, exact missing positions, types, metadata, consumption results and native ownership are checked outside the timed intervals. Package loading, fixture creation, an explicit preceding GC and final validation are excluded. Automatic GC during read and consumption is included.

All six target-route permutations are used. Controls reverse order and alternate before or after the targets; requested thread and workflow order reverse; each paired build occupies the first position three times for every case. The controller preserves every worker CSV and compares it exactly with the aggregate rows. Both builds passed the same 56 no-clock qualification cases before measurement.

The clean baseline is [9e6977a426f56b50044bf6d62c108c2d1e3548ed](https://github.com/jbearak/dta-parser/commit/9e6977a426f56b50044bf6d62c108c2d1e3548ed), the previously qualified combined integration tree. The clean candidate is [9ee3916ca078cb46f49f932b7cbb3ded70a6a99f](https://github.com/jbearak/dta-parser/commit/9ee3916ca078cb46f49f932b7cbb3ded70a6a99f). Its only runtime difference is the compatible-transfer helper and its three call sites. The benchmark controller is frozen at [daec5174f6ce8221c7d7560b8cf2431ec50743b5](https://github.com/jbearak/dta-parser/commit/daec5174f6ce8221c7d7560b8cf2431ec50743b5). Both clean build receipts use their original `baseline` receipt variant; the benchmark's comparison roles remain baseline and candidate. Source inventories, shared-library hashes, the exact Rscript launcher and R runtime, fixtures and controller dependencies are bound before and after execution.

The profiled and generic Float64 cases use the same physical file with different profile settings. Disabling the private profile also disables its checksum and metadata policy. Cross-route timings therefore do not isolate checksum or classifier costs. The valid comparison is between builds within one route.

Individual read intervals range from 5–99 ms CPU and 4–64 ms wall. Six observations do not improve the underlying timer resolution. Results cover one host, one row/column/batch geometry and an uncontrolled filesystem-cache state. They measure public read and consumption, not isolated fill throughput, process RSS or parity with Stata. No phase clocks or diagnostic counters are present in either measured build.

The publication substitutes private paths in text evidence. Completion and audit artifact hashes bind the original files; the publication source map records both original and published hashes, and the publication manifest binds the redacted copies. Published receipts and scripts therefore retain placeholder paths and are not byte-identical to the private originals. Raw numerical observations are retained.

The historical `codex/arrow-compatible-copy-measured` branch preserves those measured commits. It is a measurement reference, not a second candidate.
