# R helper performance — 2026-08-26

## Result

On the generated five-million-row compact Stata `long` column,
`factor_from_labels()` had a 114 ms median elapsed time versus 261.5 ms for
`haven::as_factor()`. `tab()` had a 146 ms median versus 303.5 ms for
`table(haven::as_factor())`.

| Operation | Median | Minimum | Maximum RSS | Peak footprint | Source materialized |
| --- | ---: | ---: | ---: | ---: | :---: |
| `factor_from_labels()` | 0.1140 s | 0.114 s | 139.3 MB | 123.0 MB | No |
| `haven::as_factor()` | 0.2615 s | 0.258 s | 280.0 MB | 263.6 MB | Yes |
| `tab()` | 0.1460 s | 0.145 s | 273.0 MB | 256.8 MB | No |
| `table(haven::as_factor())` | 0.3035 s | 0.293 s | 394.6 MB | 378.4 MB | Yes |

The package-owned factor conversion was 2.29 times as fast in this workload
and used 140.7 MB less maximum RSS. The complete one-way tabulation was 2.08
times as fast and used 121.7 MB less maximum RSS. Keeping the source compact
avoids adding its 40 MB decoded-double backing; the remaining memory difference
comes from each workflow's result and grouping state.

## Method

- Host: Apple M4 Max, macOS Tahoe 26.5.2, arm64
- R: 4.6.1, `aarch64-apple-darwin25.4.0`
- dtaparser: 0.5.0 Stage 2 working tree
- Haven: 2.5.5
- Fixture: generated Stata 10 file, 5,000,000 `long` values, three labelled
  codes in a deterministic repeating sequence
- Iterations: 12 fresh-source iterations per operation
- Statistic: median and minimum elapsed wall time from `proc.time()`
- Peak memory: one fresh process per operation under `/usr/bin/time -l`;
  maximum resident set size and peak memory footprint are reported above
- Correctness: factor values, levels, table counts, and table level names were
  identical before timing
- Storage check: each iteration began with an unmaterialized dtaparser numeric
  ALTREP; the script separately verified post-operation source state

Exact commands:

```sh
R CMD INSTALL -l /tmp/dtaparser-stage1-bench.P8YyCI r-package/dtaparser
DTAPARSER_BENCH_LIB=/tmp/dtaparser-stage1-bench.P8YyCI \
  Rscript --vanilla benchmarks/r-helper-performance/run.R 12 5000000
```

This is a report-only microbenchmark, not a timing threshold or a general
performance guarantee.
