# R cell assignment — 2026-09-19

## Result

On a 100,000-row dibble, one `repl()` call costs about 60 times one
`data.table::set()` call for a single positional row, and about 17 times for
a whole-column write. A loop of 1,000 single-row writes takes 113 ms through
`repl()` and 2 ms through `set()`. The per-row loop is the regime the ADR
declines to serve: no consumer of this package writes per row, and a loop
over a few dozen whole columns costs under 10 ms in total.

| Call | Median | Allocation | Iterations |
| --- | ---: | ---: | ---: |
| `repl_whole_column` | 122.8 µs | 781.6 KB | 200 |
| `repl_single_row` | 109.7 µs | 280 B | 200 |
| `set_whole_column` | 7.4 µs | 0 B | 200 |
| `set_single_row` | 1.8 µs | 0 B | 200 |
| `repl_row_loop` | 113.1 ms | 310.5 KB | 3 |
| `set_row_loop` | 2.0 ms | 24.0 KB | 3 |

`repl_whole_column` is `repl(d, !!name := 2)` with `name` a runtime string;
`repl_single_row` is `repl(d, x = 3, where = 5L)`, a positional row; the
`set_*` rows are `data.table::set(dt, j = "x", value = 2)` and
`set(dt, i = 5L, j = "x", value = 3)`; the loops write rows 1 through 1,000
one positional call at a time. Row selection is positional on both sides so
that neither side pays for a predicate scan; an earlier draft selected the
row with `where = id == 5L`, which charged a 100,000-element mask to every
`repl()` call and quadrupled its apparent cost.

## Method

- Host: Darwin 25.6.0 arm64 (Apple silicon)
- R: 4.6.1, `aarch64-apple-darwin25.4.0`
- dtatools: 0.10.0, built by the exact-source installer from source SHA
  `4ce15c7f5a1485f4b8febe345fe898792ee48200`, package tree
  `ffcf370dd5ce9bd40a3030ceccd257d918fcfe0e`, clean checkout; the runner
  validated the installation's provenance sidecar before timing
- data.table: 1.18.6.1; bench: 1.1.4
- Fixture: `dibble(id = 1:100000, x = as.double(1:100000))` and the same
  columns as a `data.table`, built in the runner
- Iterations: 200 per single call, 3 per loop; medians from `bench::mark()`
  with `filter_gc = FALSE`
- Correctness: before timing, each call's landed value and its neighbour's
  were checked on both containers; after the loops, rows 1 through 1,000
  held the written value

Exact command, from the clean checkout at the SHA above:

```sh
Rscript --vanilla benchmarks/r-cell-assignment/run.R
```
