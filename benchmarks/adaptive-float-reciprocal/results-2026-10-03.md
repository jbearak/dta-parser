# Adaptive compact-float reciprocal blocks

The accepted change improves public `1.01 / x` CPU time by 1.080× for sparse missing values, 1.126× for a random half-missing column, and 4.611× for an entirely missing column in the measured million-row cases. The missing-prefix case is slightly slower: 0.976× by the ratio of medians and 0.990× by the median paired-round ratio. Half-missing compact floats still take 1.922× the typed-double control. This is a scoped improvement, not general double parity.

## What changed

The earlier reciprocal kernel proves that a block of ordinary binary32 denominators can use the original binary64 division followed by output narrowing without per-result validity or fit checks. Dense missing values repeatedly defeat that proof and send rows through the exact fallback.

The first dense prototype prepared every block whenever the captured column contained any missing value. It classified missing values and zeros once, substituted a safe denominator, and retained a mask for canonical missing output. That helped dense cases but made sparse and missing-prefix columns much slower. Its complete 216-observation result is retained as a rejected experiment.

The accepted kernel tries the ordinary proof first. Only failed blocks need preparation. After four consecutive ordinary-proof failures, preparation handles the rest of the current captured span, bounded by 16,384 rows. The next span retries ordinary proofs. Unsafe prepared denominators have a separate bounded exact fallback. Ordinary and prepared quotient writers are separate loops.

A separate proof uses the captured exact missing count. If every input is missing, the existing finite-scalar, compact-float and output-type admission proves that every result is canonical missing. A bounded fill writes the fresh output without reading input spans or searching a denominator threshold. Existing read claims protect the count and source through allocation callbacks.

Both paths retain the original binary64 division and final narrowing. The denominator threshold is proved for both signs. Observed infinities, noncanonical imports, zeros and format-specific missing values keep their exact policies. Whole-column promotion recomputes from the original captured inputs. Floating-point exception-flag trace equivalence is not claimed.

## Paired public measurements

Six paired rounds compare the accepted prior reciprocal source [f219bf72](https://github.com/jbearak/dta-parser/commit/f219bf72bbc882cc4c090ded870470ab9c5e2099) with adaptive source [2ec57f24](https://github.com/jbearak/dta-parser/commit/2ec57f24a14a646ae67fd2e0af4fb8ef1c549f52). Each build/round uses a fresh R process. Build order alternates; compact and typed-double order is balanced. The unchanged typed-double implementation is a control. There is no bare R-double control in this screen.

The typed-double CPU ratios range from 0.957× to 1.029×. Normalizing each paired compact cost by its paired typed-double control gives a median prefix cost of 1.027×, with three of six rounds slower. That modest regression is retained, rather than attributed entirely to noise. The half-missing normalized cost is 0.932× and the all-missing cost is 0.220×.

The public default native threshold is unchanged at 2,048 rows. The 1,024-row case has no native scalar entry; after a primer, every measured call at or above the threshold has one. Recorded CPU and wall intervals are 205–355 ms. Per-call figures divide these retained intervals by repetitions. Timing includes output allocation and automatic GC; explicit GC, calibration, input construction, full verification and missing-cache mutation are outside the clocks. GC time is not separately recorded.

All 216 observations and 36 no-clock qualification observations pass complete values, missing masks, storage, metadata, native-entry and ownership checks. Clearing all oracle-missing result rows verifies complete cleared bytes and `anyNA(cleared_result) == FALSE`, then rechecks original result and source bytes. Ordinary input grids include zero denominators, so no input missing values does not mean no missing output.

The [accepted raw observations](evidence/accepted/screen-v1/raw.csv), [summaries](evidence/accepted/screen-v1/summary.csv), and [independent audit](evidence/accepted/independent-audit.json) retain all rounds. The [rejected screen](evidence/rejected/screen-v1/summary.csv) is published separately.

## Structural and compiler evidence

The 1,980-case actual-header probe covers all four rounding modes, both denominator signs, modern and legacy encodings, exact R NA bits, output widths, imported values, boundaries and small retained spans. The old dense candidate passes values but fails 292 work gates. The adaptive candidate passes every semantic and work gate.

For a million rows with a 256-row missing prefix, the adaptive kernel prepares 16,384 rows and uses the ordinary writer for 983,616. With every-997 missing values it prepares 70,080 rows. An all-missing input performs one million canonical output stores with zero preflight/input spans, threshold checks, classification, quotient or fit work. These counters describe source work, including failed speculative preparation and five scratch bytes per prepared row; they are not emitted instruction counts.

The actual release build and separate same-flags compiler remarks are bound to the source and installed DLL. Both preparation instantiations vectorize at width 16; ordinary proof, quotient and exact fallback loops remain vectorized. An independent review replayed those bindings. This is evidence for the measured compiler and host, not a cross-compiler guarantee.

The rejected dense candidate [2a89fd6f](https://github.com/jbearak/dta-parser/commit/2a89fd6f5af9d60fce5020688fd917238a27f441) improved random-half and all-missing CPU by 1.142× and 1.426×, but sparse and prefix gains fell to 0.549× and 0.490×. Its raw observations, summaries and independent audit remain separate from the accepted run.
