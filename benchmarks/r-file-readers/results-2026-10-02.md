# R reader follow-up, 2026-10-02

This is an incremental comparison against release 0.11.0 at
`93cc80890032da4c6ef93e8beb4f5b6eb0175a29`. The earlier reader construction
study was already merged into that baseline. Its gains are not counted again.
The final candidate keeps direct object-identity checks during dibble creation
and a per-handle cache of the immutable numeric span used by scalar ALTREP reads.
The first avoids repeated address-string creation; the second avoids repeated
native-owner/chunk lookup while visiting adjacent retained values.
[Exact build bindings and patch](results-2026-10-02/build-bindings.json),
[earlier study](results-2026-10-01.md).

The final-v2 matrix contains 1,248 R observations. It reuses 24 native Stata
observations and 480 external-reader reference observations from an earlier
completed 864-observation run. Those sources remain separate in the records.
Six pairs cover each final synthetic/default and serial case;
eight pairs cover each large control. Results below report what improved and
where intervals remain unresolved. They do not establish elimination of the
earlier tenfold CPU gap or a universal reader ranking.

## Measurement boundaries

R call wall and CPU clocks cover the same operation; CPU is process user plus
system time across all workers. Stata uses a native plugin over the same command
interval. Whole-process CPU and peak RSS include startup. Each observation is a
fresh process with warm filesystem cache. R package loading, wrapper compilation
and garbage collection precede its timer; first public reader initialization
remains timed. Read-return and read-plus-consumption
use separate processes. Consumption visits every numeric value as a double and
every string byte length; it can expose costs deferred by ALTREP or allocate
expanded numeric storage. It is a fixed R traversal, not every possible analysis.

Both profiled Arrow reads retain checksum verification; qs2 validates its checksum.
Generic Feather has no dtatools profile. Its tibble can retain Arrow ALTREP buffers.
Stata semantics and metadata differ across persistence formats, so cross-format
rankings use canonical ordinary values and cannot replace the same-file comparison.
[Protocol](README.md), [source analysis](../../docs/research/r-reader-performance-limits.md).

The final-v2 host monitor recorded 30 snapshots from 2026-10-02T03:04:34+00:00 to 2026-10-02T03:19:04+00:00.

## Rejected scalar-cache layout

The first cache implementation improved Arrow consumption but added repeatable
cost to compact DTA consumption. Its complete six-pair interim run recorded:

| Interim endpoint | Full wall change [95% interval] | Full CPU change [95% interval] |
| --- | --- | --- |
| compact DTA tibble | +4.64% [+1.20, +7.45] | +3.95% [+1.12, +6.65] |
| compact DTA dibble | +2.42% [+0.63, +5.32] | +2.33% [+0.67, +4.91] |

Assembly inspection identified a copied numeric descriptor in the getter,
which enlarged its stack frame and added work even to the plain compact DTA path.
Final-v2 uses typed scalar decoders and keeps retained-span lookup inside that
branch. Its getter uses a 48-byte frame with scalar decoding inlined; the
baseline used a 32-byte getter and transferred to a separate 48-byte decoder.
The ordinary DTA path retains the same three R API calls without an extra
cache access or decoder call. All four general decoder instruction sequences
match baseline after address normalization. Assembly explains the change but
does not establish its speed. A separate four-pair compact consumption screen
checked the revision; the complete final matrix was then rerun after rebuilding.
The interim result
is retained as rejected-implementation evidence, not pooled into final paired
estimates. The incomplete serial stage stopped during qualification and supplies
no timing conclusion. [Interim paired results](results-2026-10-02/interim/default/paired-summary.csv),
[interim build](results-2026-10-02/interim/cache-v1-build/build-bindings.json),

## Rejected uncompressed-buffer experiment

The first candidate also replaced zero-initialization followed by exact reads
with a bounded read into vector spare capacity. A two-pair synthetic screen
was exploratory. A four-pair large Arrow follow-up found the following:

- 1 GB, automatic threads: wall +1.35% [+0.90, +2.70]; CPU +3.10% [-0.51, +7.13].
- 1 GB, one thread: wall -1.55% [-3.84, -1.13].

The automatic-thread wall regression outweighed the small serial gain for
retention. The final candidate restores the original uncompressed read path.
Those screen candidates also contained the other changes, so these are not an
isolated factorial estimate of zeroing alone. Final results above use the
