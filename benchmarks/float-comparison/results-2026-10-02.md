# Direct float comparisons, 2026-10-02

Direct compact float comparisons match or beat the double controls in this
million-row constructed-column matrix. Across 432 observations, scalar
`x < 1.01` takes 0.92–1.05× typed-double CPU and 0.39× bare-double CPU on
missing-free inputs. Float pairs take 0.29–0.38× typed-double CPU and
0.88–0.89× bare-double CPU on missing-free inputs. These are warm-operation
results on one host; retained-column throughput is not measured here.

Six balanced rounds compare clean merged baseline `fd72c344` with candidate
`69422ba5`. Every public result, complete input value hash, input metadata and
compact/materialized state passes qualification. The source, installed library,
controller and execution-runtime bindings remain unchanged. The full
[observations](results-2026-10-02/timings/raw.csv),
[summary](results-2026-10-02/timings/summary.csv) and
[independent audit](results-2026-10-02/validation/independent-paired-audit.json)
retain the evidence.

## Results

CPU milliseconds per public call, including logical result allocation and
automatic garbage collection. Ranges cover automatic/single-thread settings
and missing-free/sparse-missing inputs. Speedups compare corresponding medians,
not range endpoints. Bare R missing-bearing comparisons propagate NA and have
a different contract, so the bare ratios quoted above use only missing-free
cases.

| Operation | Before CPU ms | After CPU ms | CPU speedup | Wall-time speedup | After / typed CPU |
| --- | ---: | ---: | ---: | ---: | ---: |
| `x < 1.01` | 1.630–1.899 | 0.268–0.280 | 5.81–7.10× | 1.87–5.96× | 0.92–1.05× |
| `x < y` | 2.990–3.432 | 0.629–0.639 | 4.68–5.45× | 1.43–4.74× | 0.33–0.38× |
| `x == y` | 3.319–3.740 | 0.628–0.632 | 5.28–5.96× | 1.53–5.29× | 0.29–0.33× |

The baseline's automatic setting starts several workers. Removing their CPU
cost does not imply the same wall-time gain. Single-thread runs alone improve
by 4.68–5.94× CPU across these cases, establishing that the gain also comes
from the inner loop. Typed-double pair comparisons retain their existing
implementation and remain slower than bare R in this matrix.

## What changed

The old generic loop reconstructed a double value and missing rank for each
operand at each row. The new module dispatches the operator, operand shape and
Stata release before entering a typed loop. Float pairs use 32-bit ordered keys;
scalar comparisons widen each float exactly to the unchanged binary64 scalar.
Plain float buffers use a direct call, like existing integer and double-scalar
fast paths, without creating a thread pool for each operation. Retained chunks
can use the same inner kernel through the existing region walker, but their
scheduling and span costs need separate timing.

Stata's high missing encodings help, but a blanket threshold would change this
reader's treatment of permissive imports. Modern floats recognize exactly the
27 reserved codes. Values between them, high observed values and infinities
retain the existing behavior. The ordered keys normalize signed zero and place
observed values below every missing rank. Legacy releases keep their existing
broader system-missing rule. Unrecognized NaNs decline the fast path so the
existing fallback owns the error. These rules require no new persistent
column-domain fact.

Scalar comparisons preserve the R scalar's full precision. Temporal columns
keep the existing decoder because epoch conversion can make distinct stored
floats equal after binary64 rounding. Mixed storage pairs also keep their
existing path. The change does not alter arithmetic, readers, missing-value
normalization or public result types.

## Protocol and validation

Each build runs in a fresh R process per round. Build order alternates; each
case covers all six compact/typed-double/bare-double orderings. The 36 cases per
build and round cover scalar less-than, pair less-than and equality, thread
settings 1 and automatic, and inputs with zero missing values or sparse
instances of all 27 Stata missing codes. Deterministic finite values are exact
in every representation. Direct native entry is separately qualified before
timing; the timed calls use the public operators.

Construction, explicit collection, calibration and complete correctness checks
are outside timing. Calibration targets 300 ms of CPU; retained CPU intervals
are 251–340 ms and wall intervals are 76–340 ms. Other local builds, tests and
benchmarks were stopped during measurement. This is arm64 macOS with R 4.6.1,
without hardware isolation from ordinary desktop activity. No formal confidence
interval or process-memory claim is made. The
[protocol](results-2026-10-02/timings/protocol.json) and
[build provenance](results-2026-10-02/timings/provenance-before.json) record the
host, execution runtime, exact source inventories and installed library hashes.

The bridge passes 45 Rust tests, including differential checks over missing-code
neighborhoods and sampled bit patterns. The clean candidate passes 2,912 focused
R assertions with no failures, errors, skips or warnings. Public regression
coverage includes all operators, missing ranks, retained chunks with different
boundaries, modern noncanonical values, legacy layouts, IEEE values, scalar
precision and temporal rounding. Forty-two repository Python checks and ten
benchmark-controller checks pass; controller checks also pass with Python
assertions disabled. The clean full R suite passes 54,304 assertions with no failures, errors or
skips and seven warnings in the same tests as the accepted baseline. Required
source-archive conformance passes, including R CMD check with the existing
three warnings and two notes.
