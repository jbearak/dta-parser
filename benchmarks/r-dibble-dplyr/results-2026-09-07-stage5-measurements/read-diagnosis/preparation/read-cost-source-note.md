**What the saved metrics measure.** `median_ms` is `bench::mark()`'s median elapsed time, multiplied by 1,000, with `check=TRUE` and `filter_gc=FALSE`. Fixtures, first value checks and explicit `gc()` run outside the timing call. A first result stays alive through profiling, timing and a post-read rename; the runner also checks the profiled and timed results, backing identity and source metadata. This is a retained-result workload, not a first-read-only microbenchmark. The manifests say implementation/reviewer builds and tests were paused and phases ran sequentially.

`r_allocated_bytes` sums recorded `Rprofmem()` allocation events in a separate operation call; `r_largest_allocation_bytes` is its largest event. They measure cumulative allocation and largest allocation, **not retained heap or RSS**. `bench_allocated_bytes` is `bench`'s allocation report and equals the table's R total in these rows. All six recorded native byte-counter deltas are zero on both sides. Candidate validation-scan counters are zero; baseline reports them unavailable (`NA`), not zero. These counters do not count every base-R element visit. Allocation equality does not imply equal read work. [Profiler](/private/tmp/dta-direct-stage4/benchmarks/r-dibble-dplyr/owned-double-helpers.R:131).

The separate memory runner measures `retained_with_source_vector_heap_bytes` as the post-result minus pre-result live `Vcells` count after GC, times eight, while source and result both remain alive. Its post-drop residual and release measurements are also live-vector-heap differences; whole-process maximum RSS includes startup, fixtures and validation. That runner covers rename and two pipeline lengths with 16-column fixtures, not these twelve reads. Do not attach those retained-heap or RSS results to the table. **Verified call paths.** Column lookup uses `$.dtatools_ref_data` → `.reference_column`, returning the existing column when found. There is no per-element table lookup. An owned handle stores a backing record in ALTREP `data1`; its external-pointer address caches the pointer to the exact ordinary R allocation rooted in that record. Integer/logical/string `Elt` methods load through `owned_read_pointer()` and index the cached pointer. Read-only `Dataptr` and `Dataptr_or_null` are already registered; integer/logical region and all relevant `No_NA` methods also exist. [Column lookup](/private/tmp/dta-direct-stage4/r-package/dtatools/R/mutate-data.R:2391), [backing representation](/private/tmp/dta-direct-stage4/r-package/dtatools/src/owned-columns.h:50), [getters](/private/tmp/dta-direct-stage4/r-package/dtatools/src/owned-columns.h:503), [registration](/private/tmp/dta-direct-stage4/r-package/dtatools/src/owned-columns.h:819).

The current package's [logical subset](/private/tmp/dta-direct-stage4/r-package/dtatools/src/owned-columns.h:625) explicitly requests an ordinary result from its gatherer.

R's [ALTREP dispatch](https://svn.r-project.org/R/tags/R-4-6-1/src/main/altrep.c) directly invokes `Elt` for integer/logical and, for strings, also disables/restores GC around dispatch (lines 399, 518, 627). These wrappers do not ask `Dataptr_or_null` first. Adding another missingness cache or region hook therefore cannot by itself redirect the listed base loops. There is no public ALTREP Mean hook in the pinned [API header](https://svn.r-project.org/R/tags/R-4-6-1/src/include/R_ext/Altrep.h). This explains constraints, not an impossibility result.

**Bounded experiments after the relevant Stage 5/6 work.** The useful first hypothesis is that repeated R-to-ALTREP dispatch plus backing-pointer retrieval accounts for much of the common approximately 2 ms increment per million values. That quotient is about 2 ns per value; it is not a measured getter latency.

1. Separate lookup, scan and output costs on pre-extracted columns and the original table expression. Compare safe diagnostic loops using element access, regions where available, and one rooted read-only pointer. Count element calls in a separate, untimed instrumented build. Use 100k/1M sizes and no/early/late missing values. Decompose logical mean into its missingness mask, subset and ordinary final mean. This distinguishes lookup, per-element dispatch, scan count and temporary allocation hypotheses.
2. If getter work remains material, prototype one backing-access change at a time. The getter already uses a cached address; do not assume another cache helps. Retain the exact old allocation across callbacks, detachment and GC, preserve write barriers for strings, and measure both latency and handle/retained-heap costs. A faster pointer retrieval that breaks alias isolation is not an improvement.
3. Try a narrowly eligible logical conversion hook only as a disposable proof. R's generic ALTREP success path copies attributes after `Coerce`; ordinary conversion copies them before its loop/warnings. Compare attributes/order, names/dimensions, zero-length inputs, NA, warnings/errors and callback/GC behavior before expanding scope. Existing explicit package export helpers handle owned doubles only; they do not already optimize these logical/factor flags. Factor character conversion requires its own feasibility study because base bypasses generic `Coerce`.
4. Study whether upstream R can use a read-only pointer/region in the listed primitive loops without changing semantics. Keep any R prototype separate from package qualification: a local patched R cannot establish performance on the supported stock runtime. A new visible column class, global base-method override or evaluator syntax rewrite would change the contract rather than demonstrate an equivalent storage optimization.
5. Stage 5/6's package-controlled evaluator may reduce its own repeated scans and share row planning/gathering. Measure that improvement separately. It cannot be credited with fixing arbitrary user calls to base `is.na`, `anyNA`, `as.character` or `mean`. An independent ordinary snapshot may be a useful diagnostic control; its 4/8-byte-per-value copy must be counted and cannot silently replace the shared-column contract.

Promising changes need a serialized paired rerun of the original exact matrix, the new distinguishing cases, retained-result/backing checks and existing ownership/metadata/write-safety qualification. Keep profiling separate from timing and preserve each changed source/runner identity. Additional isolated retained-memory measurements are needed before making per-read retained-memory claims. No such experiments or reruns were performed for this note; final performance acceptance remains open.
