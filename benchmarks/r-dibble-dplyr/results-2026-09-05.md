# Dibble dplyr overhead, 2026-09-05

The current dibble result path does substantial copying and repeated string
validation. The cost depends strongly on the column representation. Compact
numeric and dictionary-string columns already avoid retained-payload copies.

## Controlled comparison

Every pair starts with identical Stata column objects in an ordinary tibble and
a dibble. These are not comparisons against bare R numeric/string columns.
The following cases contain 1,000,000 rows and 16 distinct columns.

| Operation and columns | Typed tibble, ms | Dibble, ms | Tibble allocation, MB | Dibble allocation, MB |
| --- | ---: | ---: | ---: | ---: |
| Rename, regular doubles | 0.183 | 2.095 | 0.003 | 128.045 |
| Rename, compact integers | 0.186 | 0.428 | 0.003 | 0.044 |
| Rename, ordinary `dta_string` | 0.190 | 218.725 | 0.003 | 640.049 |
| Rename, declared character without `dta_string` class | 0.205 | 137.942 | 0.003 | 256.046 |
| Five `mutate(c01 = c02)` calls, doubles | 1.744 | 27.858 | 40.010 | 640.219 |
| Five `mutate(c01 = c02)` calls, ordinary `dta_string` | 12.031 | 1177.405 | 40.010 | 3216.242 |
| Filter half the rows, doubles | 134.566 | 152.956 | 1370.027 | 1434.068 |

For 100,000 rows and 32 dictionary-string columns, rename took 0.192 ms on the
typed tibble and 1.044 ms on the dibble, allocating 0.009 MB and 0.052 MB.
For a short, wide table of 100 rows and 1,000 double columns, rename took
0.592 ms versus 12.575 ms. This exposes per-column R bookkeeping independently
of large payloads.

The full matrix has 71 paired operation cases. It also includes logicals,
factors, selection, arithmetic, and mixed representations. See
[operations.csv](results-2026-09-05/operations.csv).

## Attribution

Separately measuring stages on the one-million-row, 16-column rename result
shows where the work occurs:

| Stage | Double time, ms | Double allocation, MB | `dta_string` time, ms | `dta_string` allocation, MB |
| --- | ---: | ---: | ---: | ---: |
| Snapshot | 0.010 | 0 | 0.011 | 0 |
| Isolate columns | 2.361 | 128.001 | 38.631 | 128.001 |
| Validate columns | 0.035 | 0 | 170.522 | 512.005 |
| Reconstruct, including validation | 0.074 | 0.040 | 171.776 | 512.045 |

These are separate measurements with different retention/GC conditions, not
numbers to sum into the full-call median. Raw data is in
[stages.csv](results-2026-09-05/stages.csv).

Source inspection explains the measurements:

- `.close_dibble()` isolates every result column by default, then calls the
  general `.as_dibble()` conversion path.
- `.metadata_copy()` uses lazy proxies for package compact backing but copies
  ordinary vectors. On doubles, a rename therefore allocates the retained
  numeric payload despite changing no values.
- `.type_dibble_columns()` revisits the full table. `.typed_column_named()`
  and `.typed_column()` repeat `.dta_typed_column()` checks. For ordinary
  strings, those checks scan for missing values and byte widths.
- Classed strings incur additional copies through vctrs missing checks and
  `.metadata_view()` while exposing their underlying character data. The
  CPU profile agrees with these call paths; classless declared strings are
  cheaper but still rescan all values.
- Typed `mutate()` expressions must enter the mask with Stata semantics, but
  finalization currently revisits values that have already been typed.

The typed-tibble filter baseline itself allocates 1.37 GB for 64 MB of double
output. That cost includes Stata vector slicing/restoration and is not caused
solely by dibble finalization. Optimizing the table wrapper cannot erase all
typed-vector overhead. The proposed owned-column module should also preserve
validation evidence through native slices; this needs separate measurement.

## A safe, limited prototype

For rename only, the prototype verifies source/output vector identity, retains
the existing complete isolation step, and uses an internal constructor that
does not revalidate those known-valid columns. It does not change the installed
namespace or production source.

| Columns, 1M rows × 16 | Baseline, ms | Prototype, ms | Speedup | Baseline allocation, MB | Prototype allocation, MB |
| --- | ---: | ---: | ---: | ---: | ---: |
| Ordinary `dta_string` | 213.371 | 31.579 | 6.76× | 640.049 | 128.045 |
| Declared character | 139.079 | 36.802 | 3.78× | 256.046 | 128.045 |
| Regular doubles | 2.914 | 2.563 | 1.14× | 128.045 | 128.085 |
| Compact integers | 0.434 | 0.427 | 1.02× | 0.044 | 0.044 |

Baseline and prototype were measured together in a separate run, which is why
their baseline medians differ slightly from the full matrix. Output values,
column metadata, result aliases, and both directions of later explicit mutation
passed checks. The prototype is not qualified for arbitrary verbs, callbacks,
or new storage. See [prototype.csv](results-2026-09-05/prototype.csv).

This supports shipping validation improvements first. Eliminating the remaining
128 MB of copies requires changing column ownership, not merely deleting a scan.

## Method and validation

- Source: `3a8189933a8ddd32a1bc1c5c6194956382586a20`, clean package source,
  exported with `git archive` and installed in an isolated temporary library.
- Host: Apple M4 Max, 128 GB RAM, macOS 26.5.2, arm64.
- R 4.6.1; dtatools 0.7.1; dplyr 1.2.1; vctrs 0.7.3; tibble 3.3.1;
  bench 1.1.4; Rust/Cargo 1.98.0. See [session.txt](results-2026-09-05/session.txt).
- Seven iterations per expression; medians include GC. MB means 1,000,000 bytes.
  Allocations are cumulative R allocations, not retained memory or peak RSS.
  No new generalized copy-on-write implementation was benchmarked.
- Deterministic repeated values, distinct column vectors, retained `str12`
  declarations, and a temporary DTA round-trip for dictionary storage.
- Fixture creation, library startup, and correctness validation are excluded
  from operation timing. Inputs are reused; these are warm measurements.
- Before timing each pair: equal dimensions, names, values, and column
  attributes; original values/attributes unchanged; compact input backing
  remains compact. No timing cases failed these checks.
- Focused dibble, bracket, mutation, numeric/string, copy, and slice tests passed.
  Four warnings in those tests concern existing factor export, Date comparison,
  and tibble row-name behavior.
- Full source package tests and examples passed under `R CMD check --no-manual`.
  The baseline check ended with three warnings and two notes: macOS deployment
  target linker warnings, GNU make extensions in unpacked vendor sources,
  an `_abort` symbol in the Rust archive, a vendor CITATION location, and a
  generated C file without a final newline. No production source changed.
- The source-archive content check passed. The future rename allocation guard
  failed as expected: a 100,000-row double rename allocated an 800,048-byte
  block; the typed tibble had no allocation above the 10,000-byte threshold.
