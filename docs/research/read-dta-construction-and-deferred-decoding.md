# Faster read_dta construction and deferred decoding

Findings for [issue #216](https://github.com/jbearak/dta-parser/issues/216), measured on 2026-09-09. The load, phase, workflow, sequence, memory and saved-counter results are complete and independently reviewed. The recommendation is to implement direct reader construction and keep this deferred numeric design in research.

Direct construction has a measurable benefit for wide numeric and fixed-string inputs. In the 1,000-row, 1,024-double case, the current dibble path took 16.950 ms and the direct variant 8.453 ms. Stata took 0.523 ms on the same file. Avoiding repeated R construction work therefore addresses part of the gap. The benefit is not uniform: direct's median decreased in 23 of 28 cases and increased in five strL cases. All cases and signed differences remain in the [complete comparison table](read-dta-evidence/load-comparison.csv).

Deferred decoding asks a different question: can an analysis avoid converting columns it never uses? The current reader already defers expansion of compact numeric storage and materialization of R strings. It still decodes selected numeric cells and constructs selected string dictionaries before returning. The private numeric prototype retains owned row-major input blocks and decodes a complete column on first use. Its correctness checks and measurements are separate from the constructor matrix.

## What the current reader does

The native reader allocates typed columns, decodes selected observations, attaches column and dataset metadata, then returns a tibble. Freshly decoded doubles are adopted without copying their values. R subsequently performs string-class checks, name repair, tibble conversion, metadata handling and general dibble conversion. Metadata must be attached before the reference marker because existing metadata replacement can use the frame's bracket-assignment method. [Native completion](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/src/rust/src/lib.rs#L3188-L3300), [R completion](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/R/read-dta.R#L185-L346), [metadata updates](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/R/dta-metadata.R#L317-L427).

General dibble conversion repeats name, shape, type and capture checks over the returned columns. These numeric checks are principally proportional to column count; the source does not establish a second full numeric-value copy. String declaration validation also scans each dictionary's entries to check maximum width. That part can grow with distinct values, so it is not merely fixed per-column overhead. [Dibble constructor](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/R/dibble.R#L171-L218), [typing and declaration checks](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/R/mutate-data.R#L3007-L3134), [dictionary-width scan](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/src/init.c#L7405-L7428).

Known `col_select` first invokes a separate full metadata open to obtain selection metadata, then opens the reader again. The preflight does not decode observations and normally does not materialize value-label tables. The ordinary block decoder reads the complete observation-row width even when it returns only selected columns. Projection can therefore save decoding and allocation without reducing those row-block bytes. It should not be equated with skipping all bytes of unused columns. [Selection ABI](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/R/read-dta.R#L449-L471), [metadata implementation](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/src/rust/src/lib.rs#L3370-L3449), [observation plan](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/src/dta-tools/src/file.rs#L639-L698).

## Deferred numeric prototype

The private prototype starts from the same package tree and supports numeric-only release-118 files. Its modified installation has the separate identity `issue216-numeric-snapshot-source04-de83-8bc09dba`. It copies owned row-major observation blocks, publishes deferred numeric handles, then calls existing numeric kernels when a column is first forced. Each handle caches a complete converted column. It retains full observation-row bytes even for projection. Capture and forcing are serial. This is a bounded experiment, with no new public lazy API.

An owned buffer remains valid after the input is replaced, deleted or cleaned up as a temporary source. It does not make initial copying atomic against concurrent in-place writes. A file mapping alone would not supply the same immutable ownership contract. Strings and strL require their own design: fixed strings must defer dictionary construction, while strL must distinguish eager structural indexing from deferred payload decoding and decide when malformed unused payloads should fail.

A private file copy is another possible backing, which could reduce retained process memory at the cost of staging and repeated strided reads. This research measures the owned-buffer implementation only. Remote inputs would need the same ownership transfer before temporary-source cleanup; raw/gzip witnesses cover that cleanup mechanism locally, while HTTP failures and Windows file lifetime remain untested. [Current source resolution and cleanup](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/R/read-dta.R#L366-L445).

Structural layout, selection and metadata validation remain eager in the prototype. Numeric value conversion moves to first force. It rejects files containing any string or strL column, including when that column is unselected, and rejects other format releases. A future string implementation would need an explicit error-timing policy. Current strL indexing checks structure and references separately from payload conversion; delaying either changes when malformed input can fail. It must also preserve the current text policy, including UTF-8 defaults for modern releases, Windows-1252 defaults for older releases and replacement of invalid UTF-8. None of those string behaviors is newly qualified by this numeric prototype. [strL indexing](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/src/dta-tools/src/file.rs#L6372-L6542), [payload conversion](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/src/dta-tools/src/file.rs#L6575-L6670), [text decoding](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/src/dta-tools/src/text.rs#L7-L75).

Both current and direct R completion preserve laziness in the tested 32-row, seven-column control: zero force attempts, completed cells and cache publications immediately after return. Both retain 1,120 observation bytes. Current creates 54 handles and direct 33 before GC. First access decodes the selected 32-cell column once; repeated access in that sequence reuses its cache. This is evidence for that access pattern, not a promise that every duplicate shares one cache.

The successful controls cover five numeric storage widths, both byte orders, system and all 26 canonical tagged missings, signed-zero bits, temporal values, metadata, projection/windows/empty results, file overwrite/deletion, returned-handle lifetime, tested alias writes, unread duplication, serialization and error recovery. A separate five-file qualification checks all 2,520,000 ordered values and the actual storage-width cycles. Mutation checks use the prototype's explicit force adapter where required; they do not establish support for every optimized dibble write path.

The numeric controls establish parity with current conversion kernels on canonical missing codes. Official Stata format documentation also describes noncanonical floating values between named missing codes as missing; the current Rust and compact-C classifiers recognize aligned codes. This research preserves that existing distinction and makes no complete format-conformance claim. The official installed format help was inspected and identified locally; its contents are excluded from the archive. [Official format help](https://www.stata.com/help.cgi?dta), [current missing-value classifiers and tests](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/src/dta-tools/src/missing.rs#L158-L340).

The actual measurement worker also passed 30 complete frame-and-consumed-result checks across baseline, private eager and deferred routes. Four raw/gzip lifetime checks returned with zero forces after wrapper-owned temporary files had already been removed, then matched the full baseline. These local checks do not establish remote HTTP behavior. Independent restoration of every saved record required the exact private ALTREP namespace; the first namespace-free reviewer failure is retained.

The prototype counters report raw-byte length and capacity, handle counts and completed conversion work. They are not a complete ledger of native allocations or decoded-cache bytes. The separate Rprofmem, process-heap and peak-RSS measurements are needed to assess memory cost; none can be added to the raw-byte counter as an independent allocation total.

The worker pilots expose repeated decoding in ordinary workflows. A small-fraction workflow and its known one-column selection each complete three whole-column decodes. A progressive sequence ends at nine decodes across eight source columns. The one-column selection still captures all 26,000 row bytes of the selected small file. These are per-handle caches, so a once-per-source-column claim would be incorrect. Both retained snapshot pilots release their raw observation bytes and live handles after dropping the result. Pilot numerical values are excluded from the estimates.

A real SIGINT cancels first force with no completed column or cache publication. Retrying the same handle returns all four million expected values and publishes one complete cache. A separate finalizer experiment ran after the handle was ready, so it did not establish reentry during decoding. That combined diagnostic therefore exited one despite the successful interruption/retry assertions. The recursive-force guard has source review, with that runtime witness still absent.

The controls compare named frame metadata with exact values and nested ordering. Direct construction changes the order of otherwise identical top-level attributes; it is not a byte-identical R object. A signed-zero fixture preserves the writer's original bytes and records a single owned eight-byte correction because the current writer canonicalizes a double negative zero in that path. The reader oracle remains independent, and no writer change is part of this research.

R consumers can request full materialization through data-pointer access, serialization or a full scan. A lazy implementation must also preserve missingness, duplication and thread rules. `datasig=TRUE` already signs all values before returning. Deferral therefore needs measurements of complete downstream work, not just return time. [R compact-representation API](https://cran.r-project.org/doc/manuals/r-release/R-exts.html#Writing-compact_002drepresentation_002dfriendly-code), [R API thread rule](https://cran.r-project.org/doc/manuals/r-release/R-exts.html#The-R-API), [datasig call](https://github.com/jbearak/dta-parser/blob/c90425825a57509ff815b543368858032f73bb8f/r-package/dtatools/R/read-dta.R#L185-L346).

Sequences contain seven iterations with ten phases each and 100 empty-clock observations per process, giving 3,060 rows. Each iteration reloads its table, then retains that table across its ten phases. Each process includes its first iteration, with visible first-use outliers; these distributions are separate from the warm batch estimates. Empty-clock values are retained without subtraction, and a rounded zero does not establish zero cost. [Sequence medians and ranges](read-dta-evidence/numeric-sequence-summary.csv).

Reading its first scalar takes 0.085/0.112 ms, with same-handle repeated access at 0.050/0.056 ms. The later all-column phase takes 1.826/5.774 ms. In the five-width case, expanding the fraction to 25% takes 2.360 ms eager and 10.014 ms deferred. Post-GC R heap is especially easy to misread here. For the double full traversal, eager/deferred retained vector-heap deltas are 10,830,896/629,224 bytes, while their process peaks remain near 150 MB. This difference is not proof that the deferred table has shed its backing or that native caches are free. The saved counters show that this all-column summary still retains 10,240,000 native observation bytes after GC, with 128 live handles and 128 completed decodes. After the retained GC, datasig instead records zero raw bytes while retaining 128 live handles. Before collection, its after-batch observations range from zero to the full raw buffer, and the allocation-profile checkpoint retains the full buffer. This is no immediate-release guarantee. After dropping either result and collecting, retained raw bytes and live handles are zero. Completed decodes aggregate across cloned handles; they do not count currently resident caches or explain every allocation. The access operation matters to lifetime, even when both workflows consume all values.

The saved-counter exporter decoded all 8,824 plain Stats records, and a separate CSV assessment reaggregated all 722,639 source-column rows to their checkpoint totals. These are cumulative source-column counters across cloned handles, not per-handle traces. After-batch observations describe only the final call in a batch; eager counters remain unavailable. The [final-call](read-dta-evidence/numeric-counters-matrix-final-call.csv), [allocation](read-dta-evidence/numeric-counters-allocation-after.csv) and [retained checkpoints](read-dta-evidence/numeric-counters-retained-checkpoints.csv) preserve those boundaries.

The [progressive-access counters](read-dta-evidence/numeric-counters-sequence-after.csv) agree across all seven iterations in both numeric families. For 128 columns, load and handle access perform no decoding. First scalar access completes one whole column; same-handle and new-extraction repeats add none. The small-fraction phase reaches seven cumulative completions, the 25% phase 38, and the final all-column phase 165. For 1,024 columns those later totals are 52, 307 and 1,330. Some source columns are decoded three times. Caching works for the tested repeated handle, but does not eliminate repeated conversion through copied handles. All 108 post-release snapshot checkpoints record zero retained raw bytes, raw capacity and live handles; that does not imply zero process-heap residue.

## Recommendation

Implement a dedicated constructor for the native reader's already validated columns. Preserve name repair, metadata-before-reference ordering and the ownership contract, while avoiding repeated general conversion checks. The wide numeric and fixed-string results justify this bounded change. The general dibble constructor still needs its validation for arbitrary caller inputs, and the private shortcut's selected-fixture controls do not replace qualification of the eventual public path.

Keep the deferred numeric implementation as a research prototype. It offers earlier return and lower sparse-use peak memory on some inputs, but its small-fraction benefit is inconsistent and every full-traversal/signature comparison is slower than direct eager construction. Known-selection workflows also regress in all ten numeric cases. This implementation should not become the reader default or a new public lazy API.

A further deferred experiment should first address cache sharing across duplicated handles with correct write detachment, per-column force/setup cost and lost parallel conversion. It must measure the complete workflow again, including ordinary R consumers, replacement and partial writes, serialization, interruption and raw-owner release. The current prototype's explicit mutation adapter and tested access patterns leave production integration work unresolved.

For strings, investigate deferred dictionary construction and strL payload conversion separately. The measured wide strL bottleneck is predominantly native work, so constructor cleanup has limited room to help it. Decide structural and unused-payload validation timing before changing behavior; preserve encoding, missingness and metadata contracts. An owned file copy could be compared with owned row buffers, but a mapping or retained path alone does not establish immutable source lifetime.

Use existing column selection when the needed columns are known, particularly for wide inputs. Its metadata preflight can outweigh the saving on narrow inputs, as the complete table shows. Keep the unknown-column workflow as a separate target. None of these results closes the measured gap with Stata or establishes cold-cache performance.
