# R reader mechanisms worth testing in dta-tools

Research date: 2026-09-15. This note inspects primary documentation and source. It does not add benchmark results or propose replacing the readers with another package.

## Main findings

The strongest R-specific ideas are to preserve native column buffers through the R boundary, choose string storage according to repetition, and keep expensive conversion outside work that does not need it. dta-tools already does much of this. Adding ALTREP or more workers is therefore too vague to be a useful next architecture step.

Two source details sharpen the comparison. Arrow R can expose eligible primitive buffers directly through ALTREP, while its string converter explicitly disallows parallel conversion. data.table parses into thread-local buffers and serializes R string creation inside an OpenMP critical section. Native parsing throughput and construction of R objects are separate costs. [Arrow conversion source](https://github.com/apache/arrow/blob/main/r/src/array_to_vector.cpp), [Arrow ALTREP source](https://github.com/apache/arrow/blob/main/r/src/altrep.cpp), [data.table R adapter](https://raw.githubusercontent.com/Rdatatable/data.table/master/src/freadR.c).

## Arrow R: retain a native representation, convert deliberately

`read_parquet()` returns a tibble by default, or an Arrow Table with `as_data_frame = FALSE`. It exposes `col_select` and memory mapping. Its reader properties enable multithreading by default and expose dictionary-reading controls. The underlying R6 reader offers schema inspection, selected-column reads, row-group reads and batch readers. This is a useful separation between opening a file, choosing work and selecting the destination representation. [R entry point and properties](https://github.com/apache/arrow/blob/main/r/R/parquet.R), [ParquetFileReader API](https://arrow.apache.org/docs/r/reference/ParquetFileReader.html).

The C++ reader has separate controls for batch size, buffered input, parallel column decoding and remote read coalescing. Its documentation recommends batches and avoiding prebuffering when memory matters more than throughput. Dictionary output is an explicit option for columns with repeated values. The C++ default for parallel column decoding differs from R's default, so language bindings must be inspected individually. [C++ Parquet reader](https://arrow.apache.org/docs/cpp/parquet.html#performance-and-memory-efficiency).

Parquet and IPC must remain distinct in a comparison. Parquet stores encoded pages, including compressed page payloads when compression is enabled. Memory mapping those bytes does not turn them into R doubles or decoded Arrow arrays. Arrow IPC already uses Arrow's columnar layout. R's `read_feather()` exposes projection, memory mapping and the same Table-versus-tibble choice. This suggests testing IPC buffer adoption before adding another storage format. [Parquet file format](https://parquet.apache.org/docs/file-format/), [page compression](https://parquet.apache.org/docs/file-format/data-pages/compression/), [Arrow IPC reader](https://arrow.apache.org/docs/r/reference/read_feather.html).

Arrow R's converter tries ALTREP first. Otherwise it allocates the destination R vector before scheduling chunk conversions. Its character converter reports `Parallel() == false` and constructs strings with `Rf_mkCharLenCE`; numeric conversion can fill disjoint slices in parallel. This supports a design in which workers transform native bytes, while the R thread allocates and publishes R objects. [Conversion implementation](https://github.com/apache/arrow/blob/main/r/src/array_to_vector.cpp).

Arrow's ALTREP data retains a shared `ChunkedArray` owner. Eligible primitive arrays with one chunk and no nulls can expose the existing values pointer. Other layouts materialize an R vector; nulls require R missing-value sentinels. Strings support element conversion and whole-vector materialization, and the latter drops the retained Arrow owner. These are conditional copy savings, not a blanket guarantee. Dta-tools must also preserve its different mutation and Stata missing-code contracts. [ALTREP ownership, pointers and materialization](https://github.com/apache/arrow/blob/main/r/src/altrep.cpp).

Arrow's Dataset interface postpones execution until `collect()` or `compute()`. Projection avoids unnecessary columns. Partition values can eliminate files, and Parquet row-group statistics can eliminate groups. Unsupported operations on a Dataset error; unsupported operations on an in-memory Table can trigger collection into R. Therefore a fast `open_dataset()` call is not a completed import. A useful comparison includes the first result actually consumed in R. [Dataset execution and pruning](https://arrow.apache.org/docs/r/articles/dataset.html), [Table conversion and execution boundary](https://arrow.apache.org/docs/r/articles/arrow.html).

## data.table fread: eager output with staged native work

`fread()` samples across a memory-mapped file to infer types and estimate allocation, then reads into typed columns. Out-of-sample type changes can trigger rereading the affected columns. Selection avoids output for dropped columns. DTA already supplies its schema and row width, so copying CSV type inference would add work; the transferable idea is to prepare allocation and dispatch once. Its compression and command paths may first create a temporary uncompressed file. Those costs belong in an end-to-end read comparison. [fread reference](https://rdatatable.gitlab.io/data.table/reference/fread.html).

The implementation is more specific than the reference page's broad assertion that fread uses no C buffers. `pushBuffer()` receives thread-local row-major buffers. It handles strings first inside one critical section, calls `mkCharLenCE`, and writes strings to the final R vectors. Non-string loops then copy strided buffer values into contiguous output columns outside that critical section. This lets string publication overlap other workers' parsing and numeric copies. It is evidence for separating these phases, not evidence that an additional transpose would benefit dta-tools. [Current adapter implementation](https://raw.githubusercontent.com/Rdatatable/data.table/master/src/freadR.c#L556).

data.table's own benchmarking guidance calls out R's global string cache. Initial import pays to add character values, while later operations can benefit from the cache. Compare both cold R processes and repeated reads, then include the downstream operation. Otherwise a reader that paid string interning earlier can appear worse than one that postpones it. [data.table benchmark guidance](https://rdatatable.gitlab.io/data.table/library/data.table/doc/datatable-benchmarking.html).

## vroom and readr: laziness has a scope and an ownership cost

vroom first indexes field locations and retains access to the mapped input. Lazy columns convert values when accessed. The official ALTREP configuration enables character columns by default; numeric ALTREP is optional. Its benchmark article explicitly includes later operations and describes numeric-heavy inputs as an unfavorable case for the index representation. The article's performance tables use 2021 versions, so this note uses the mechanism and measurement lesson without treating its rankings as current evidence. [ALTREP defaults](https://vroom.tidyverse.org/reference/vroom_altrep.html), [indexing design and benchmark scope](https://vroom.tidyverse.org/articles/benchmarks.html).

The current character ALTREP implementation keeps an external owner, registers a finalizer and forces duplication on modification. Element access uses the indexed bytes and locale encoder, checks missing strings and can report parsing problems. `Dataptr` materializes the entire character vector; materialization releases the index information. Thus neither printing a sample nor returning a tibble establishes that all strings have been decoded or all value-dependent errors reported. [vroom character implementation](https://raw.githubusercontent.com/tidyverse/vroom/main/src/vroom_chr.h).

readr's second edition calls vroom, but current `read_*()` functions default to `lazy = FALSE`. They support selection and threading, with a documented single-thread fallback for newlines inside quoted fields. Their parsing problems are warnings with details available through `problems()`. These CSV semantics are not a substitute for dta-tools' malformed-input rejection contract. [readr architecture](https://github.com/tidyverse/readr), [current reader reference](https://readr.tidyverse.org/reference/read_delim.html).

The readr maintainers changed the default back to eager in 2.1.0 after problems with retained file handles and reading followed by overwriting the source. This is direct experience relevant to any file-backed DTA proposal. Preserve an owned result after `read_dta()` and `read_arrow()` return, or introduce a separately named open/scan API with a documented lifetime. A memory map alone does not provide an immutable snapshot against changes to the mapped file. [Maintainers' explanation](https://tidyverse.org/blog/2021/11/readr-2-1-0-lazy/), [local owned-backing research](read-dta-construction-and-deferred-decoding.md#deferred-numeric-prototype).

## What dta-tools already has

- Native allocation and parallel decoding are present. Workers receive disjoint columns, write preallocated numeric buffers and build Rust-owned string dictionaries without calling R. The string builder deduplicates owned strings, keeps row IDs and recognizes repeated cycles. An alternative must beat these existing paths on their favorable inputs. [R sink and dictionary builder](https://github.com/jbearak/dta-parser/blob/573e636611d5b73afde47f5d5f232c3c4bcc506f/r-package/dtatools/src/rust/src/lib.rs#L2486).
- Both readers have a dedicated reader-container route. It reuses the native tibble shell for dibble output, preserves name repair and attaches metadata before publishing the dibble. The current `.new_reader_dibble()` still loops through columns for typing and capture checks. Treat further constructor simplification as a measured refinement of an existing route. [Output construction](https://github.com/jbearak/dta-parser/blob/573e636611d5b73afde47f5d5f232c3c4bcc506f/r-package/dtatools/R/output-container.R#L45), [reader dibble constructor](https://github.com/jbearak/dta-parser/blob/573e636611d5b73afde47f5d5f232c3c4bcc506f/r-package/dtatools/R/dibble.R#L226).
- DTA projection resolves names through a metadata preflight before the native read. The block reader still uses complete row widths. Arrow projection reads selected column buffers and overlapping record batches, with selected-field profile validation for predicate-free selection. Type predicates and full reads have broader validation obligations. [DTA wrapper](https://github.com/jbearak/dta-parser/blob/573e636611d5b73afde47f5d5f232c3c4bcc506f/r-package/dtatools/R/read-dta.R#L277), [Arrow contract and wrapper](https://github.com/jbearak/dta-parser/blob/573e636611d5b73afde47f5d5f232c3c4bcc506f/r-package/dtatools/R/read-arrow.R#L25).
- The Arrow wrapper captures one open file identity for selection and reading, then closes it after returning owned columns. The native snapshot is a `File`, not a memory map. This existing open/read separation can support better plan reuse. It does not itself prove immunity to concurrent in-place writes. [Snapshot implementation](https://github.com/jbearak/dta-parser/blob/573e636611d5b73afde47f5d5f232c3c4bcc506f/r-package/dtatools/src/dta-tools/src/arrow/read.rs#L135), [read lifecycle](https://github.com/jbearak/dta-parser/blob/573e636611d5b73afde47f5d5f232c3c4bcc506f/r-package/dtatools/src/dta-tools/src/arrow/read.rs#L1913).

## Candidate experiments for architecture agents

These are hypotheses inferred from the mechanisms above. None has a claimed speedup.

| Candidate | Concrete change to investigate | Experiment that would reject or narrow it |
| --- | --- | --- |
| Preserve owned IPC buffers through R publication | Let compatible native owners back compact columns; avoid coalescing or copying merely to cross the R boundary. Keep default checksum verification. | Count live input, decompressed, concatenated and final buffers by type and batch. Compare read plus first full scan, then mutation, aliasing, serialization and source deletion. Reject if retaining chunks increases peak memory or makes common full scans slower. |
| Choose string representation by repetition | Compare the current dictionary with owned UTF-8 bytes plus offsets for high-distinct fixed strings and strL. Preserve dictionary storage for repeated strings. | Sweep distinct fraction, byte width, encoding and repeated-cycle structure. Measure dictionary building, retained bytes, first R string access and all-string materialization separately. Reject a universal switch if repeated strings regress; reject adaptation if its sampling and conversion cost exceeds savings. |
| Prepare selection and conversion once | Reuse validated schema and selected-field plans across the R/native calls. Carry explicit evidence that allows the reader constructor to skip checks already performed. | Sweep tiny, wide files and known versus predicate selections. Count opens, metadata parses, R calls and per-column checks. Reject if remaining time is mostly value decoding, or if malformed/profile/name-repair parity needs the allegedly redundant work. |
| Bound in-flight Arrow work by bytes | Reuse the Parquet lesson that batch count and prebuffering trade memory for throughput. Bound decoded buffers awaiting R publication. | Vary record-batch width, thread count and compressed/uncompressed buffers at fixed total input size. Record wall time and peak native bytes. Reject if queue limits only reduce throughput while final output dominates memory. |
| Add an explicit scan path for partial analyses | Push selection and supported predicates before R object construction, retaining owned native data or a clear file lifetime. Extend the existing direct execution work where possible. | Compare read-plus-filter-plus-summary, sparse access and full consumption. Include error timing, file replacement, temporary-source cleanup and interrupts. Reject default-reader laziness if the advantage disappears on full consumption. |

For all experiments, qualify semantic read parity as defined in [CONTEXT.md](../../CONTEXT.md). Keep Stata system and tagged missings, temporal conversion, string encoding, labels and profile validation in the measured path. Report at least reader return, first selected operation and complete consumption. The [earlier deferred numeric study](read-dta-construction-and-deferred-decoding.md) already found enough limitations to keep its row-major deferred prototype out of the default reader; new proposals need a different mechanism or workload to justify revisiting that decision.
