# Plain and grouped mutation in dplyr and data.table

September 29, 2026. This is a source comparison, not a benchmark or an implementation plan. The installed packages inspected here report dplyr 1.2.1 and data.table 1.18.6.1. The dtatools comparison is the isolated PR clone at `74b95ccf964020d148f558adb445c39090e123ca`; the original workspace was left alone. dplyr links point to its [1.2.1 release](https://github.com/tidyverse/dplyr/releases), tagged at `9574097`. Its current development tree reports 1.2.1.9000; I checked that readable source alongside the [published 1.2.1 source](https://cran.r-project.org/src/contrib/dplyr_1.2.1.tar.gz). data.table links point to a [fixed CRAN mirror commit](https://github.com/cran/data.table/tree/ba42d9d35804332f92acc21dbba9f8dce2f3ec98), whose three cited files match the [1.18.6.1 source archive](https://cran.r-project.org/src/contrib/data.table_1.18.6.1.tar.gz) byte for byte. The proposed directions still need their own semantic and cost tests.

## dplyr

`mutate.data.frame()` computes grouping information, collects quosures, calls `mutate_cols()`, then installs the resulting columns through `dplyr_col_modify()` before placement and retention filtering. `mutate_cols()` creates one `DataMask`, installs error and warning handlers, evaluates each expression in order, and records which input columns were used. The mask validates names, retains group row lists, creates lazy chops for input columns and bindings for their names. These are real setup steps even for a simple numeric expression. [mutate source](https://github.com/tidyverse/dplyr/blob/v1.2.1/R/mutate.R), [data mask source](https://github.com/tidyverse/dplyr/blob/v1.2.1/R/data-mask.R).

The C++ evaluator loops over groups, sets the current group, evaluates the quosure, and checks each result. A result must be a vector of group size or size one; the latter is recycled. R code casts compatible chunks and `list_unchop()` assembles the full column when there is more than one group. `dplyr_col_modify.data.frame()` recycles the final columns, turns the data into a list of column references, replaces named entries, and reconstructs the data frame. It does not blindly copy every numeric column's bytes. For a grouped frame, it retains the existing `group_data()` when no grouping variable is modified and computes new groups when one is modified. [C++ mutate evaluator](https://github.com/tidyverse/dplyr/blob/v1.2.1/src/mutate.cpp), [R mutate assembly](https://github.com/tidyverse/dplyr/blob/v1.2.1/R/mutate.R), [column modification methods](https://github.com/tidyverse/dplyr/blob/v1.2.1/R/generics.R).

The group plan has a concrete representation: keys plus a `.rows` list. For a transient `.by`, `compute_by_groups()` calls `vctrs::vec_group_loc()` and keeps its key and location outputs. The existing grouped-frame path reads `group_data()`. This makes group metadata reuse conditional on key stability, not a general license to skip regrouping. [Grouping source](https://github.com/tidyverse/dplyr/blob/v1.2.1/R/by.R), [column modification methods](https://github.com/tidyverse/dplyr/blob/v1.2.1/R/generics.R).

## data.table

For an ungrouped `DT[, name := rhs]`, the R layer parses the special `:=` expression, checks column capacity and evaluates `rhs` before calling `Cassign`. `assign.c` keeps an internal self-reference to detect a copied table or names vector. When more column slots are needed, `shallow()` copies the column-pointer list and related attributes, then retains the payload column vectors as references. An exact-length whole-column RHS can replace the destination pointer in `Cassign`; a shared, reused, or ALTREP RHS is copied first. This is not an in-place arithmetic kernel for `x + 1`: R still computes that RHS. [R `:=` dispatch](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/R/data.table.R#L1142-L1282), [self-reference and shallow copy](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/src/assign.c#L3-L133), [whole-column assignment](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/src/assign.c#L584-L618).

For a subset or scalar RHS, `Cassign` allocates an NA-filled new column if needed and uses `memrecycle()` to write selected rows or a contiguous span of an existing column. Its numeric cases write payload elements directly after type and recycling checks. It also records the affected column and adjusts key or secondary-index metadata after a write. `set()` is a shorter R-to-C assignment entry, with fewer expression-processing steps than `[.data.table`. The constructor has different ownership rules: `as.data.table.list()` builds a fresh list and copies full-length input vectors, so constructor behavior should not be inferred from `:=`. [Assignment and metadata updates](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/src/assign.c#L358-L659), [`memrecycle()`](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/src/assign.c#L706-L1059), [`set()`](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/R/data.table.R#L2899-L2913), [constructor source](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/R/as.data.table.R#L185-L237).

For grouped `:=`, the R layer computes order, group starts and lengths, and prepares one reusable `.SDall` buffer sized for the largest group. `dogroups.c` updates `.N`, `.GRP`, `.BY` and `.I`, fills the group slice, evaluates `j` once per group, checks the result length, and writes selected rows into the target through `memrecycle()`. It allocates a new output column once rather than constructing one full-column result per group. Reusable `.BY` and `.SD` objects require copying when an expression puts them inside a returned list column; the source handles that case explicitly. Eligible grouped aggregations have a separate GForce path that computes results in bulk, but it is not a general grouped-mutate path. [Group preparation](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/R/data.table.R#L1577-L1665), [group evaluator and writes](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/src/dogroups.c#L105-L359), [GForce dispatch](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/R/data.table.R#L1844-L2021).

## What maps to dtatools

dtatools already has a narrow no-mask path for callback-free scalar `gen()` and replacement. `.generate_direct_scalar()` requires a simple name, scalar binding and selection, then calls the native generator; `.replace_direct_scalar()` sends the same kind of value to `C_dtatools_patch_scalar`. A general vector RHS enters `.mutate_data()`, which captures private column views, handles group plans, resolves expressions, and commits through a generated-column or replacement transaction. These guards protect dtatools' public evaluation order and by-reference alias rules. [Direct scalar paths](../../r-package/dtatools/R/mutate-data.R), [general mutation](../../r-package/dtatools/R/mutate-data.R), [native transaction](../../r-package/dtatools/src/mutation-transactions.c).

For grouped assignment, `.assignment_groups()` reuses a grouped tibble's `.rows` metadata or calls `vctrs::vec_group_loc()` on selected keys. `.grouped_mutation()` evaluates `where` and `values` per nonempty group, collects row and value pieces, resolves duplicate selected rows in favor of the last value, and restores row order before a native write. `.mutation_selection()` already computes a group plan once for a bracket call and passes it into each assignment. A proposal to reuse groups therefore has to name a narrower repeat computation and prove that callbacks, key aliases, row reorders, and prior writes cannot invalidate it. [Group selection](../../r-package/dtatools/R/assignment-groups.R), [group evaluation and gathering](../../r-package/dtatools/R/mutate-data.R), [bracket caller](../../r-package/dtatools/R/dibble.R).

The best plain-vector question is whether a proved ordinary or package-owned full-column numeric RHS can reach the existing bounded native reader and writer with less setup around it. The source already copies a selected contiguous REAL input in blocks and falls back to the ordinary decoder when its storage or values are uncertain. data.table's whole-column pointer assignment is a useful comparison for avoiding a second value copy, but dtatools must still preserve its own value ownership and by-reference table contract. Any earlier path must preserve validation, missing-code normalization, metadata, observable getters, value evaluation, alias isolation, interrupt order and the first error. [Generation reader](../../r-package/dtatools/src/mutation-transactions.c), [replacement staging](../../r-package/dtatools/src/mutation-write.h), [R generation dispatch](../../r-package/dtatools/R/mutate-data.R), [data.table whole-column assignment](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/src/assign.c#L584-L618).

For grouped work, upstream code suggests checking the cost of setting up masks and assembling results from group pieces, not assuming a new hash loop will help. In particular, data.table reuses group buffers and writes validated results into the destination as it goes; dtatools creates row and value pieces, then gathers, deduplicates and orders them before commit. A prospective direct writer would need to retain dtatools' last-write-wins row rule and its left-to-right publication behavior. The first proof should identify a repeated setup step in one current call and show which public method, finalizer, key mutation and published-prefix histories it must still observe. A source comparison cannot turn that into a speed claim. [dtatools group loop](../../r-package/dtatools/R/mutate-data.R), [dplyr group evaluator](https://github.com/tidyverse/dplyr/blob/v1.2.1/src/mutate.cpp), [data.table group evaluator](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/src/dogroups.c#L194-L359).
