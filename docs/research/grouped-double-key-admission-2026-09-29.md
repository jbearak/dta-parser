# Grouped double keys: a narrow admission seam

Source inspected in the isolated `e85cbc352fe7e289884f3bc72376cc37b252e7d3` checkout on 2026-09-29. The grouped C routes still admit compact `dta_long` keys, even when the arithmetic source is already an owned `dta_double`. This note is source research, not a performance or semantic qualification. Selected local source hashes are at the end.

The ordinary grouping machinery explains why changing only a class test would be wrong. Bracket selection opens private column views, then `.assignment_groups()` groups their keys with `vctrs::vec_group_loc()` and retains that selection for all assignments in the bracket call ([assignment-groups.R](../../r-package/dtatools/R/assignment-groups.R), lines 28-95; [mutate-data.R](../../r-package/dtatools/R/mutate-data.R), lines 1915-1965). Ordinary dibble `.by` also uses `vec_group_loc()`, but reads the physical table after begin-result captured a shallow output shell ([dibble-expressions.R](../../r-package/dtatools/R/dibble-expressions.R), lines 4-29 and 415-445). This matches [dplyr 1.2.1's `.by` grouping path](https://github.com/tidyverse/dplyr/blob/v1.2.1/R/by.R); [vctrs documents](https://vctrs.r-lib.org/reference/vec_group.html) first-appearance groups and a key column of the input's prototype. data.table takes another route: its grouped evaluator binds each group's rows and evaluates `j` for that group in [`dogroups.c`](https://github.com/cran/data.table/blob/ba42d9d35804332f92acc21dbba9f8dce2f3ec98/src/dogroups.c). Its by-reference write path is not a reason to skip dtatools' public grouping and alias checks.

The current fast paths have three different key capture contracts:

* Bracket `source + 1` admits an owned `dta_double` source but passes the key to `canonical_long()`, `numeric_base_source()`, and `private_key_reader()`. Its plan snapshots decoded values, builds first-appearance groups, creates an owned-real group key carrying the compact key's `class` and `stata.storage`, then rechecks descriptor identity and bytes after callback-capable work ([probe-grouped-bracket-batch.c](../../r-package/dtatools/src/probe-grouped-bracket-batch.c), lines 757-875; [probe-grouped-bracket-plan.c](../../r-package/dtatools/src/probe-grouped-bracket-plan.c), lines 17-40 and 212-335). A plain REAL or owned `dta_double` key has no compact base: `numeric_base_source()` explicitly returns `NULL` for both ([numeric-payload.c](../../r-package/dtatools/src/numeric-payload.c), lines 313-320). Changing `canonical_long()` alone would break the reader and mislabel the output key as `dta_long`.
* Grouped `gen` reads the key from the input table, requires compact `dta_long`, roots its `numeric_base_source()` and `data1`, snapshots with `numeric_region()`, then checks slot, metadata, descriptor and full key bytes again before append ([probe-grouped-gen.c](../../r-package/dtatools/src/probe-grouped-gen.c), lines 163-190 and 239-405). Its accepted key integer domain includes zero and negative values down to `-2147483647`; the bracket and early dibble routes require `1..INT_MAX`. A shared reader must leave each caller's validation domain intact.
* Early dibble grouped mutate captures columns before group planning. It snapshots the **physical** planning key after that capture, then forks the **captured** columns for output. It compares the output key fork with the snapshot only when the planning key is the originally captured key ([grouped-dplyr-admission.c](../../r-package/dtatools/src/grouped-dplyr-admission.c), lines 840-1015). A callback can change the physical slot between capture and planning. Requiring the physical and captured key to be identical unconditionally would change the ordinary continuation.

For finite, positive, exactly integral values, a plain REAL key and a `dta_double` key appear able to produce the same group partition as compact `dta_long`: the package's `vec_proxy_equal.dta_numeric()` returns `rank,value`, with rank zero when there are no missing values, while plain REAL uses vctrs' default equality ([dta-numeric.R](../../r-package/dtatools/R/dta-numeric.R), lines 724-772; [vctrs proxy contract](https://vctrs.r-lib.org/reference/vec_proxy.html)). This is only a value-level argument. The owned key invokes a public S3 equality method; the plain key does not. The method can be replaced or traced, and the ordinary path can produce different errors or observable call history. Missing values, signed zero, nonintegers, unusual attributes, ALTREP, and custom equality methods remain on the existing ordinary path until proved separately.

**Smallest source change worth designing:** give each existing caller a key-kind-specific snapshot/seal adapter, without widening its source, expression, public-guard or publication rules. Limit the first admitted forms to exact unclassed, unattributed, non-ALTREP REAL and exact unexposed owned-real `dta_double` with its current two plain metadata attributes and rooted backing. Read each at the caller's existing capture phase into a private protected REAL snapshot; retain the exact original key and, for owned-real, its backing owner. Before publication, recheck the original slot/handle, extent, metadata, owner, and snapshot bytes after every callback-capable interval. Pointer equality cannot replace byte rechecking: a key can alias the arithmetic source or another column. Construct the group-key column according to the ordinary vctrs key result, rather than copying `dta_long` metadata. In particular, any extra `REAL()`/backing access, allocation, root, poll, or public getter needs its own ordering and lifetime review.

I would start the proof with the bracket planner because its selection helper is separate and already has a final key seal. Compare ordinary `vec_group_loc()` group order, key column class/storage and aliases, and full public call/error order for plain and owned-double keys under a source-plus-constant call. Then treat grouped `gen` and early dibble mutate separately at their stated capture phases. Preserve the existing fallback whenever an ordinary key's public dispatch or metadata cannot be matched. The current slow benchmark cells establish motivation, not expected savings.
