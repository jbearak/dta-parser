Stage 7 retained-memory preparation

`memory-v2.R` runs one operation in a fresh R child, always reading the original source and replacing the latest result. It measures group_modify identity, group_nest or nest_by at width8 plus a key and128 groups. The intended full row counts are100k and1M. This is repeated use of a fixed input, not a recursively nested chain.

The seven heap checkpoints are prefixture, source only, after5 calls, after50, after final validation, source released and result released. At5/50 only the source and latest result remain live. Scalar/address state frames are written to CSV and then released; no accumulating table of state records remains in memory. The small heap-record list and fixed metadata schemas are bookkeeping. Full expected payload vectors are created inside final validation, after the50-call checkpoint. They are not retained as a payload oracle across the measured repetitions. Source and result schema, values, keys, prototypes and grouping indices must pass the same independent checks as the timing driver.

The native state function is an exact copy of `stage7_states` from operations-v2.R. It records ordinary owned and compact/fallback payloads separately. Integer fixture input normalizes to compact Stata long behind a metadata wrapper; this is not an ordinary owned double. No claim that every result column is owned follows from its recorded state. Remaining source and result state requirements are assessed from actual records.

`run-memory-v2.py` adapts run-stage7-v2.py only to require a single route/workload/row count and wrap the same R entry in the pinned `/usr/bin/time -l`. It binds time before Git source lookup, retains complete actual argv and parses exactly one macOS maximum-resident-set-size record. That byte count covers the whole R child, including setup, repeated calls, validation and runtime recording. It is separate from the heap checkpoints and from individual-operation allocation. Existing fixed Git, installation, support-schema, source-copy, input inventory and namespace/DLL guards remain.

The memory child performs no foreign writes. A separate tiny repeated-output witness must verify the original source, an early saved output and the latest output before the memory evidence qualifies. The unsafe public predecessor nesting path must not be subjected to those writes; its read-only memory observations retain that limitation. The fixed predecessor safe reference and candidate public route require the separate witness.

This is unexecuted preparation. Root coordinates quiet acceptance measurements after candidate functional gates. Small execution smokes may run earlier and carry no performance acceptance. The source pieces named memory-v1-prefix.R, memory-state-function-v1.txt and memory-v1-suffix.R were joined to create the complete selected memory-v2.R; execution reads only that complete file and the four explicitly bound support files.

The v2 source selects support-v2/validation-v2.R with exact width-summary value checking. Other memory semantics and state function are unchanged. A first v1 small predecessor-reference memory workload completed R validation, but sandbox time failed on sysctl and produced no RSS. A second exact v1 run outside the sandbox completed with seven heap checkpoints and a whole-child RSS record. Neither is full quiet memory acceptance. The v2 retained-output witness is still required.
