# dtaparser R package versus haven: 2026-07-24

This run benchmarks the experimental `dtaparser::read_dta()` R API introduced
on top of the JavaScript parser. It uses a persistent, in-process V8 context;
there is no Node/Bun subprocess startup in any measured read.

## Environment and command

The environment matches the
[direct parser run](2026-07-24-apple-m4-max.md): Apple M4 Max, Darwin 25.5.0
arm64, R 4.6.1, and haven 2.5.5.

```sh
npm run benchmark:r-package -- 100000 2 5
```

Each generated v118 dataset contained 100,000 rows. Results are medians after
two untimed warmups and over five measured iterations.

## End-to-end R results

| Dataset | `dtaparser::read_dta()` | `haven::read_dta()` | dtaparser throughput relative to haven |
| --- | ---: | ---: | ---: |
| Numeric, 20 columns | 984.19 ms | 75.51 ms | 0.08x |
| Mixed, seven columns | 294.25 ms | 76.36 ms | 0.26x |

The R package is substantially slower even though the underlying JavaScript
parser is faster in the direct Bun benchmark. The decomposition explains the
reversal.

## dtaparser R-package attribution

| Stage | Numeric | Mixed |
| --- | ---: | ---: |
| Read file into R raw vector | 1.85 ms (0.2%) | 0.65 ms (0.2%) |
| Transfer bytes from R to V8 | 0.94 ms (0.1%) | 0.30 ms (0.1%) |
| Parse and build JavaScript result | 26.04 ms (2.6%) | 22.27 ms (7.6%) |
| Transfer result from V8 to R | 296.68 ms (30.1%) | 78.71 ms (26.8%) |
| Build attributed R tibble | 550.28 ms (55.9%) | 179.06 ms (60.9%) |
| Composition/GC/timer residual | 108.41 ms (11.0%) | 13.26 ms (4.5%) |

The generic V8 bridge serializes millions of JavaScript cells into nested R
lists, after which R traverses them again to create typed, attributed columns.
Those two output stages account for roughly 86% of the numeric read and 88% of
the mixed read. JavaScript parsing itself remains a small share.

This result makes the next optimization target concrete: a competitive R
package needs a native or columnar bridge that writes directly into R vectors,
or a parser output mode that transfers typed columns without nested-list
serialization. Optimizing Stata byte decoding will not materially improve this
first R-package design.
