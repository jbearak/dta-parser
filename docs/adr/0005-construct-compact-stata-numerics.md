# Persistent Stata storage types with compact construction

Users who recode variables in memory-constrained environments need derived columns to keep the same read-mostly compact representation as imported ones, and a future `write_dta()` needs each column's Stata storage type to survive an R session so that read–write round-trips can be lossless. Neither is possible unless the column itself carries its storage type, so each numeric column will bear a persistent vctrs-backed class recording it, and the package will export storage-named constructors — `stata_byte()`, `stata_int()`, `stata_long()`, `stata_float()`, and `stata_double()` — plus a `stata_storage_type()` inspector. Construction enforces each storage type's range and precision rules (including binary32 rounding for `float`), preserves `.a` through `.z`, and rejects unrepresentable values; values appear to R as doubles.

Mutation preserves the storage type wherever R's dispatch allows: subset assignment, `replace()`, and vctrs-aware verbs such as `dplyr::mutate()` and `if_else()` re-validate against the storage type and return compact results. Base whole-column constructions that strip attributes by design — notably `ifelse()`, whose result takes attributes from its condition — return plain doubles, and the constructors are the re-encode step that returns such output to compact storage. Re-encoding transiently materializes the column as doubles, so the memory win is steady-state (many columns held compact), not peak.

The vctrs methods follow a lossless-promotion lattice ordered by representable values: `byte` ⊂ `int` ⊂ `long` ⊂ `double` and `byte` ⊂ `int` ⊂ `float` ⊂ `double`, with `long` and `float` meeting at `double` because neither represents the other exactly. `vec_ptype2()` of two storage types returns their least upper bound in that lattice; combined with a bare double, integer, or logical vector (the literals in an `if_else()` or `replace()`), the storage type wins, so recodes stay typed. `vec_cast()` into a storage type validates every value: out-of-range or fractional values for the integer types error rather than silently promoting or truncating, since a silently widened column would change the declared on-disk type behind the user's back — the remedy is an explicit wider constructor. Casting to `float` permits binary32 rounding, matching the constructor. Arithmetic (`vec_arith()` and the group generics) follows Stata's own `replace` semantics: the result is re-encoded at the narrowest storage type, no narrower than the operands' least upper bound, that represents every result value. Adding one to in-range `stata_int` category codes stays `stata_int`; a result that overflows or goes fractional promotes to whatever type the values require, up to `double`, rather than erroring. The cost, inherited from Stata, is that an arithmetic result's declared type depends on the data. Explicit casts and constructors remain strict — there the user named the type, and vctrs combination casts decide types before seeing values — so a recode that injects an unrepresentable literal into a typed column errors with the wider constructor as the remedy.

We rejected a generic constructor because the storage-specific name is the user declaring the column's on-disk type, which `write_dta()` should read rather than infer; `stata_double()` is included for the same reason even though an R double is already eight bytes. A `.where` argument and reusable recipes were rejected because ordinary R expressions and subset assignment already cover conditional construction. Variable and value labels stay in the existing metadata helpers. This ADR does not itself promise `write_dta()`; it establishes the representation that makes it possible. Lossless there will mean value-identical re-read — a written file read back yields the same values, storage types, missing codes, and labels — not byte-identical files; construction-time range and precision enforcement is what makes that bar reachable.

This supersedes the earlier draft's rejection of persistent Stata vector classes: without a persistent class, no R mechanism lets mutation preserve a column's storage type.
