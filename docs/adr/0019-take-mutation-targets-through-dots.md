# Take gen and replace_values targets through dots

`gen()`, `repl()`, and `replace_values()` are declared as `(data, ..., where = NULL)`. The target column and its values arrive in `...`, either as the positional pair `variable, values` or as one tagged pair `variable = values`, optionally followed by one untagged `where`. A name held in a string is spelled `!!name := values` or `.(name) := values`, the same tags the plural label setters accept. Exactly one target is set per call; two tags or a tag after an untagged argument is an error, so `gen()` stays a one-variable command rather than a second `mutate()`.

The tagged spelling requires the pair to live in `...`, and that choice removes the named formals `variable` and `values`. Callers who spelled `gen(data, variable = x, values = 1)` now generate two tagged columns and receive the shape error; no call in the repository used that form. Two alternatives were rejected. Keeping `variable` and `values` as exact-match formals after `...` would have preserved those calls but left an unusual signature that has to be documented as "exact name only" forever. Appending `...` after the existing formals would have kept the signature familiar, but `gen(data, adjusted = x, eligible)` would then have bound `eligible` to `variable`, and partial matching would have kept `var`, `val`, and `w` unusable as column names. Moving the pair into `...` makes `values` and `variable` ordinary column names and makes `where` the only argument that must be spelled in full.
