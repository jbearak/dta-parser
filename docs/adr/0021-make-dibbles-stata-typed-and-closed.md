# Make dibbles Stata-typed and closed under dataset operations

A dibble is a Stata dataset held in a tibble, and two invariants follow. Every numeric and string column of a dibble carries Stata storage, and every dataset operation that takes a dibble returns a dibble. One mapping from bare R vectors to Stata storage applies wherever a column enters a dibble: `dibble()`, `as_dibble()`, the readers, `gen()`, `:=`, the dplyr verbs, base `transform()` and `within()`, and the replacement operators `$<-`, `[[<-`, and `[<-`. Integer becomes `long`, double becomes `double`, `Date` a `float` date, `POSIXct` a `double` datetime, character the smallest fitting `str#` or `strL`, and a `dta_*()` result keeps its declared storage. Logical columns stay logical and factors stay factors; `save_dta()` writes them as `byte` and as a value-labelled `long`, as it already did. Columns no Stata storage can hold, such as raw or `difftime`, pass through unchanged and are refused by the writer. Closure covers dplyr verbs including `summarise()`, joins with a dibble on the left, `bind_rows()` with a dibble first, base `subset()`, `transform()`, `within()`, `head()`, `rbind()`, `cbind()`, and `[` subsetting, implemented once through dplyr's reconstruct hook, vctrs' restore hook, and the existing snapshot boundary. Every result is a fresh object and the input is unchanged. (ADR 0023 later made the replacement operators the exception: they write into the dibble by reference.) A base data frame that acquired reference state through `gen()` is not a dibble and gets none of this; a tibble becomes a dibble at its first `gen()` and its existing columns are typed then.

Before this decision the two properties held for some paths and not others. `gen()` and `:=` typed their columns as `float`, matching Stata's `generate`, while `mutate()`, `$<-`, and `dibble()` itself left bare R vectors that `save_dta()` later wrote as `long` or `double`. So `data[, y := x * 2]` and `mutate(data, y = x * 2)` produced different files from the same expression, nothing in the printed output distinguished them, and the `mutate()` result was a plain tibble that had also lost the bracket form. The alternatives were to document that only `gen()`, `:=`, and `replace_values()` produce Stata storage, which leaves the trap in place, or to type `mutate()` alone, which moves the seam rather than removing it. The mapping departs from Stata's `float` default deliberately: `float` cannot hold every R double or any integer above 2^24, and one lossless rule is easier to hold in mind than one rule per verb. Users who want `float` wrap the value in `dta_float()`, as they already did for `int` or `byte`. Logicals are the exception because Stata has no boolean type and typing a flag as `byte` breaks `filter(data, flag)`, `which(flag)`, and `where = flag`, which are too common to give up for a type the writer already handles.

When an operation overwrites a typed column, the column keeps its storage if every new value fits and otherwise widens to the narrowest storage that holds every new value exactly. This is promotion, not Stata's `replace` ladder, which sends an overflowing `long` to `float` and loses digits above 2^24; dtatools goes to `double`, for the same reason the default is `double`. `replace_values()` and `repl()` stay strict and refuse values that do not fit, so a user who wants Stata's guardrails has them and one who wants dplyr's contract that the right-hand side defines the column has that. A consequence is that a bare Arrow string read into a dibble now carries the width of its dictionary, so `replace_values()` refuses a wider replacement where it previously accepted one; `:=` and `mutate()` promote. Plain Arrow files written by other tools, and reads with `profile = FALSE`, keep the reader's promise that they never acquire Stata semantics: they read as tibbles by default, and an explicit `output = "dibble"` types them. This decision narrows ADR 0020's statement that most dplyr verbs return plain tibbles from a dibble. The mapping and the promotion rule are documented once, on the `stata-storage-defaults` help page, which the `gen()`, dibble, and `save_dta()` pages reference.
