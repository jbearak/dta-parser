# Make the replacement operators write to a dibble by reference

`$<-`, `[[<-`, `[<-`, `names<-`, `dimnames<-`, and `row.names<-` on a dibble now write into the dibble's reference state and return the same object, as `gen()`, `replace_values()`, and `:=` do, so every binding to the dataset sees the change and a replacement inside a function reaches the caller's dibble. Because R desugars `var_label(data$x) <- "Age"` into ``data <- `$<-`(data, "x", `var_label<-`(data$x, "Age"))``, every metadata setter used in replacement form becomes by reference on a dibble with no new API: `var_label<-`, `val_labels<-`, and `attr<-` on `format.stata`, notes, note numbers, characteristics, and string storage. The typing and promotion rules of ADR 0021 and 0022 apply unchanged; a vector assigned in is wrapped copy-on-write so the frame it came from is never reached; `copy_data()` gives an independent dibble and `as_tibble()` a copy with R's semantics; on a tibble or data frame that is not a dibble the operators keep R's copy-on-modify behaviour.

ADR 0020 and 0021 had the replacement operators build a fresh dibble from the snapshot, which left the dibble inconsistent with itself: `data[, x := v]` reached every alias while `data$x <- v` reached only the binding assigned to, and at top level `val_labels(d$x) <- v` silently rebound `d` to a new dibble whose reference state its former aliases no longer shared, so a later `:=` on either side stopped reaching the other. The practical cost showed in translating Stata scripts, which set variable formats and labels inside functions with `data.table::setattr()` and depend on the caller seeing them: 59 such calls in the first translated project had no dtatools equivalent, and the project could not drop data.table. The alternative considered was a new by-reference setter verb alongside the copying operators. It was rejected because it would add API for a distinction users cannot see, leave the top-level decoupling in place, and still not cover `attr<-` on arbitrary metadata. Making the operators by reference is the smaller change and the one a user who chose a by-reference container expects; the semantic shift is confined to dibbles and is recorded here and on the dibble help page.
