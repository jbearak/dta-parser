# Add a dibble container with bracket mutation

dtatools adds a third output container, the dibble: a tibble subclass that carries package reference state from creation rather than acquiring it at the first `gen()`. Readers return dibbles by default, `dibble()` and `as_dibble()` construct them, and `save_arrow()` records `"dibble"` as the stored output container. Only a dibble supports the bracket form `data[i, j, by]`, because dtatools cannot own `[` on plain data frames or tibbles and cannot intercept it on data tables, whose own `:=` has different storage, missing-value, and type-promotion semantics. `gen()` and `replace_values()` continue to accept every supported container.

The bracket form follows data.table's `data[i, y := value]` shape, with `i` a row selection and `j` one or more `:=` assignments, and it stops there: `j` is not a general expression, and `.SD`, `.GRP`, and `.BY` are not provided, so summaries stay with dplyr. Unlike `gen()` and `replace_values()`, `:=` creates a missing column and overwrites an existing one, which is what a user of the data.table shape expects. Several assignments in one `j` apply left to right, each seeing the columns the previous one wrote, and each commits or fails on its own, so a failed second column leaves the first written, as two Stata lines would. Rows are selected once for the whole `j`, before any assignment writes, so a later assignment cannot change which rows an earlier one selected.

Group-wise assignment is Stata's `by varlist:` rather than data.table's: groups are formed first, then `i` and the values are evaluated on each group's rows, and `.N` is the group's row count while `.n` is the within-group row number. data.table selects rows first and groups only the selected rows, so `.N` differs between the two under a non-empty `i`; the manual states the difference. Groups come from `by`, from `bysort`, or from dplyr grouping on the input, and giving `by` or `bysort` to an already grouped input is an error rather than a silent precedence rule. `bysort` sorts the dataset by reference on all listed columns, groups by the same columns, and rebuilds dplyr grouping metadata when the input was grouped; it never sorts silently under `by`, and Stata's parenthesized sort-only keys are not supported, so `bysort id (date):` is a preceding sort line plus `by`. `gen()` and `replace_values()` accept the same `by` and `bysort` arguments and grouped inputs, sharing one grouped-evaluation engine with the bracket form, so a `by:`-prefixed Stata line translates to one call in either spelling. Multi-column `j` under groups runs column by column across all groups, keeping `.n` and `.N` constant across the assignments of one call.
