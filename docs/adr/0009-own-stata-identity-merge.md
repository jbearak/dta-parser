# Own a Stata-identity merge

Neither base `merge()` nor dplyr joins can reproduce Stata's key identity for columns read by `read_dta()`. R matching treats system missing `.` and every extended missing `.a` through `.z` as one missing value, so rows that Stata would keep apart match each other, sometimes into an accidental many-to-many expansion. The research note in `docs/r-joins-with-stata-columns.md` also records why the obvious seams fail: base `merge()` sometimes keeps only the left key, so column methods never see right-key metadata, and it owns dataset reconstruction; dplyr's equality proxy doubles as its missingness definition, so encoding the 27 codes as comparable values makes vctrs report them nonmissing and changes unrelated missing-data behavior. That proxy change was prototyped and rejected. The package will therefore own one merge function, `stata_merge()`, that matches keys under Stata missing-code identity while returning the original Stata vectors.

The interface follows Stata's `merge` command rather than base `merge()` or the dplyr join family, but the two data arguments are named `x` and `y` for consistency with base `merge()` and the dplyr joins; `x` plays the role of Stata's master dataset and `y` the using dataset; match results are named `"x"`, `"y"`, and `"match"`, with `"master"` and `"using"` as permanent aliases because they are the vocabulary Stata users bring to the function. The caller supplies `x`, `y`, explicit key names shared by both (`by`), and a required merge relationship: `"1:1"`, `"m:1"`, or `"1:m"`. Either input may also be a DTA file path, read through `read_dta()` with default arguments, mirroring Stata's `merge ... using filename`; only the merged result then occupies the caller's workspace, and a merge that needs non-default read arguments reads the file first. Many-to-many is rejected; Stata's own manual warns that `m:m` merges are almost always wrong, and a caller who wants a cross of duplicate keys should say so with a different tool. The default result keeps every row, as Stata does. `keep` filters rows by match result and `assert` errors when a disallowed match result occurs, mirroring Stata's options of the same names. The function always generates a `_merge` variable, a `stata_byte` column keeping Stata's 1, 2, and 3 codes under value labels that use the arguments' names, x only (1), y only (2), and matched (3), and errors when either input already has that name. One deliberate divergence: Stata re-sorts the merged dataset by key, while `stata_merge()` returns master rows in master order followed by unmatched using rows in using order. Key order would force the package to define and pay for Stata's sort of 27 missing codes on every merge; callers who need it can sort afterward, and stable input order is the more useful default in R pipelines.

Equality is Stata's: `.` matches only `.`, and each of `.a` through `.z` matches only itself, in every key column, with no option to weaken this. Stata-faithful identity is the reason the function exists; a caller who wants R's missing bucket already has base `merge()` and dplyr. A non-canonical `NaN` payload in a key errors, because it has no Stata identity to match under; the remedy named in the error is `NA_real_` or `tagged_missing()`. The implementation builds an internal tag-preserving proxy per key column, the observed value plus its missing code, and matches on that proxy, so `vec_proxy_equal()` and the package's R-facing missingness contract stay unchanged.

Reconciliation reuses the vctrs policies the package already ships. Key columns coalesce into their common Stata storage type through `vec_ptype2()` and `vec_cast()`, which promote storage losslessly, keep the master's variable label unless it is absent, and combine compatible value-label tables with a warning when one code's text conflicts. Overlapping non-key variables follow Stata's rule: matched and master-only rows keep the master's values, and using-only rows take the using values, cast through the same common-type policy; there are no suffixed duplicate columns. Stata's `update` and `replace` options are out of scope until someone needs them. The dataset label and notes come from the master, as in Stata, where a single scalar label cannot hold two definitions. The result is a tibble; sliced columns pass through the existing proxy-and-restore methods, so compact byte, int, long, and float backing is re-encoded in the output even though matching reads each key column's doubles once.

We rejected masking `base::merge()` with an S3 method because `read_dta()` returns plain tibbles, and giving them a package class to enable dispatch would change the read contract for every consumer. We rejected a `stata_left_join()`-style verb family because it multiplies the interface while losing the relationship, `keep`, and `assert` model that makes Stata merges checkable. We rejected exporting a surrogate-key helper for use with dplyr because it is shallow: every caller would rebuild the proxy, run the join, and restore key metadata by hand, which is exactly the complexity a package-owned merge hides.
