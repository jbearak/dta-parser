# Support data.table as a package-wide container

dtatools supports ordinary data tables across exported whole-table operations rather than limiting compatibility to selected entry points. `read_dta()` uses a shared package output default, while `read_arrow()` first restores a recorded tibble or data-table container and uses the package default only when the file has no recorded preference; an explicit reader argument overrides either rule. Reader construction changes the output container without materializing compact numeric or dictionary-string columns. `dta_merge()` defaults to the resolved `x` input's class and also accepts an explicit output choice. Data-table mutations use container-specific implementations, including physical insertion of generated columns, so later data.table operations see the same table as dtatools. Replacement retains dtatools' native casting, compact-column, transaction, and alias semantics while invalidating keys and secondary indexes that depend on the changed column. Other mutations likewise preserve unaffected keys and indexes, invalidate state that depends on changed values or structure, and always leave a valid self-reference and column capacity. Mutating and table-producing operations reject custom data-table subclasses; writers may consume their underlying data but do not preserve the custom class. Arrow datasets do not serialize runtime data-table state such as keys, indexes, allocation capacity, or self-reference.
