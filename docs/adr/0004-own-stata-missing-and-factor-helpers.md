# Own Stata missing and factor-conversion helpers

The original package boundary delegated tagged-missing construction, inspection, and label-based factor conversion to haven because haven is a widely used suggested dependency. Investigation against haven 2.5.5 found that this boundary gives up Stata-specific guarantees which dtatools can enforce at its own data seam. Haven's tag inspectors materialize compact dtatools columns; its constructor accepts tags outside Stata's `.a` through `.z` domain and preserves uppercase rather than normalizing it; and its inspector classifies some noncanonical NaN payloads as tagged values. Its factor conversion can also merge distinct codes that share display labels and omit distinctions needed to represent Stata missing codes.

The R package will therefore provide `tagged_missing()`, `missing_tag()`, and `is_tagged_missing()` under names that do not mask haven. The helpers will accept only Stata's `.a` through `.z` tag domain, recognize canonical tagged-missing payloads, preserve structural attributes, and inspect compact dtatools columns without allocating their decoded double backing. Haven remains an interoperability target in the repository test suite, not a declared package dependency.

The package will also provide `factor_from_labels()` as an intentional one-way conversion to an ordinary R factor. It will preserve distinct source codes, apply Stata label and missing-value semantics, and share a streaming conversion implementation with `tab()` so neither call materializes compact source columns. A reversible factor class, haven or forcats generic registration, and adjacent haven helpers remain outside this interface.

The trade-off is another package-owned public interface whose binary representation and interoperability need ongoing tests. CI installs a pinned haven 2.5.5 release for repository-only conformance tests. Ordinary package checks do not install Haven. This is deliberate Stata-domain ownership, not a goal of reproducing Haven generally.
